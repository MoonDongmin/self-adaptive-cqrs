# 층1 이상신호 탐지 — 순수 LLM 판정 vs 도메인 룰북 주입 비교

> 논문 Evaluation 층1(탐지)의 ablation 실험 보고서. **같은 시스템·같은 데이터·같은
> 모델(qwen3.5-9b, llm-only 모드)**에서, 관찰자 에이전트에 주입하는 컨텍스트만
> (1차) 서술형 지시 프롬프트 → (2차) **구조화된 도메인 이상값 판정 룰북**으로 바꿨을 때의
> 탐지 성능 변화를 측정한다. 발상은 Claude Code 의 CLAUDE.md 처럼 **rule 문서로
> 에이전트의 행동을 조정**하는 방식이며, 룰북은 독립 마크다운 파일로 분리되어 코드
> 재빌드 없이 반복 실험할 수 있다.
>
> 실험일: 2026-07-13 / 평가 러너: `scripts/eval/run-layer1-detection.mjs`

## 1. 요약 (확정 수치)

| 지표 | 1차: 순수 LLM | 2차: 룰북 주입 | Δ |
|---|---|---|---|
| Recall (loose, 윈도우 단위) | 92.0% (46/50) | **98.0% (49/50)** | **+6.0%p** |
| Recall (strict, scene 지목) | 50.0% (25/50) | **58.0% (29/50)** | **+8.0%p** |
| 오탐율 FPR | 8.67% (39/450) | **0.00% (0/450)** | **−8.67%p** |
| 정밀도 (strict 기준) | 39.1% | **100%** | **+60.9%p** |
| 하드 네거티브 통과 | 4/5 | **5/5** | +1 |

**재현성**: 룰북 조건(v2·윈도우8)은 **독립 실행 4회에서 전 지표·유형별 수치·미탐
파일(01330)까지 완전 동일**했다(2026-07-13 ~ 07-14, §2 실행 목록). 4회 중 2회는
층2 분석(35B)이 같은 LM Studio 에서 동시 실행 중이었는데도 수치가 흔들리지 않았다
— temperature 0 + 서버 자원 경합 하에서도 탐지 판정이 결정론적으로 재현됨을
의미한다(경합은 지연·재시도로만 나타나고 판정 결과에는 영향 없음).

LLM 판정 대상인 **센서 값 채널 6종(30건)만** 좁혀 보면:

| 지표 | 1차: 순수 LLM | 2차: 룰북 주입 |
|---|---|---|
| Recall (loose) | 86.7% (26/30) | **96.7% (29/30)** |
| Recall (strict) | 16.7% (5/30) | **30.0% (9/30)** |

핵심 결론: **rule 주입은 오탐을 사실상 소거(39→0)하면서 재현율을 동시에 끌어올렸다.**
특히 1차의 최약점이던 급변(jump) 탐지는 룰북의 의무 계산 라인(R6-CHECK)으로
loose·strict 모두 1/5 → **5/5 만점**이 됐다.

## 3. 처치 설계 — 도메인 이상값 판정 룰북

### 3.1 1차 실패 모드 진단 (룰북이 공략한 표적)

1차(서술형 지시 프롬프트) 실행의 오탐 39건·미탐 4건을 분석해 세 가지 실패 모드를 확인했다:

| # | 실패 모드 | 증거 (1차 실측) |
|---|---|---|
| F1 | **경계선 산수 회피** — 출력 억제 지시 하에서 급변(Δ>0.10) 비교를 암산으로 하다 실패 | jump 4건 미탐: 쌍이 같은 윈도우에 나란히 있었는데도 Δ=0.110 vs 0.10 판정 실패 |
| F2 | **임계값 환각** — 베이스라인의 참고용 분포 통계를 임계값으로 오용 | 오탐 39건의 주 패턴. 예: "z1=0.178 > 상한 0.1998" (0.1998은 관측 클러스터 수치, 게다가 부등호 자체가 거짓) |
| F3 | **scene 지목 부정확** — 윈도우는 맞게 울리는데 위반 scene 특정이 흐림 | 센서 6종 strict 5/30 (loose 26/30과 대비) |

### 3.2 룰북 구조 (`src/sensor-observer/sensor-observer-rulebook.md`)

판정 규칙을 프롬프트 서술문에서 **rule ID 체계를 갖춘 독립 문서**로 승격했다.
주입 순서: `[역할 프롬프트] + [(R) 룰북] + [(B) 수기 베이스라인]`.

| 요소 | 내용 | 표적 |
|---|---|---|
| R1~R5 | 도메인·물리·정합 규칙(임계값 명시), **조용히 수행 + 통과 서술 전면 금지** | F2, 토큰 폭발 방지 |
| R6 + R6-CHECK | 같은 scene 쌍마다 `선행 z평균 → 후행 z평균, Δ vs 0.10` **계산 라인 의무 출력**(생략 시 판정 무효) — 산수에 토큰 사용을 명시적으로 허용하는 유일한 예외 | F1 |
| 임계값 화이트리스트 | "판정 근거는 R1~R6 뿐, 분포 통계(예: 0.1998)는 임계값이 아니다", 부등호 재확인 의무, 애매하면 정상 | F2 |
| 출력 계약 | offendingSceneKeys 는 레코드 JSON 에서 **글자 그대로 복사**(발명 금지), 위반 요약은 rule ID + 관측값 + 부등호 인용 | F3 |
| 출력 앵커 | **응답 첫 글자는 R6-CHECK 또는 \`\`\`json** — 서술형 문장으로 시작 금지 | 반복 루프 봉쇄 (§5.3) |
| Few-shot 예시 | 가상 scene 번호로 된 위반/정상 출력 예시 2개 | 형식 준수 |

### 3.3 주입 방식 — 규칙은 코드가 아니라 문서다

룰북은 CLAUDE.md 가 Claude Code 에이전트에 주입되는 방식과 같은 구조로, **코드 밖의
마크다운 문서를 매 관찰 호출마다 시스템 프롬프트에 이어 붙인다**:

```
system = [역할 프롬프트] + "\n\n" + [(R) 룰북] + "\n\n" + [(B) 베이스라인]
           ↑ 코드(불변)         ↑ md 문서(가변)       ↑ md 문서(가변)
```

- **역할 프롬프트**(`sensor-observer.prompt.ts`): "판정 근거·오판 방지·출력 계약은
  (R)을 그대로 따른다"는 역할 선언과 JSON 출력 형식만 남긴 최소 골격. 규칙 내용 없음.
- **(R) 룰북**: `sensor-screener.ts` 의 `readSensorObserverRulebook()` 이
  `src/sensor-observer/sensor-observer-rulebook.md` 를 **호출 시마다 디스크에서
  읽어** 주입한다. 따라서 룰북 수정은 재빌드·재시작 없이 다음 윈도우부터 즉시
  반영된다 — 본 실험의 v1→v2 반복(체인 비교 금지, 출력 앵커 추가)도 전부 파일
  수정만으로 이뤄졌다.
- **(B) 베이스라인**(`sensor-value-baseline.md`): rule 이름·기대 범위의 근거 사전.
  룰북이 "여기 없는 임계값은 발명 금지"로 참조하는 화이트리스트의 실체다.

이 분리로 도메인 전문가는 TypeScript 를 만지지 않고 룰북 문서만 갱신해 에이전트의
판정 기준을 바꿀 수 있다.

## 4. 결과 — 유형별 탐지율

각 셀은 `strict 탐지 · loose 탐지`(가운뎃점 구분)다. strict = 판정이 위반 scene 을
정확히 지목(`offendingSceneKeys` — "범인 지목"), loose = 해당 파일이 포함된 윈도우가
트리거됨(`batchSceneKeys` — "경보 울림"). 층1의 경보 역할에는 loose 로 충분하나,
층2 분석이 자동으로 이어지려면 strict 가 필요해 둘을 분리 보고한다. 분수 표기(5/5)와의
혼동을 피하려고 구분자로 `/` 대신 `·` 를 쓴다. 코드 채널 4종(payload-drift,
zod-reject ×2, projection-map-failed)은 파일 단위 검사라 윈도우/지목 구분이 없어
(strict = loose) 단일 값으로 표기한다.

| 이상 유형 | 1차: 순수 LLM (strict · loose) | 2차: 룰북 (strict · loose) | 비고 |
|---|---|---|---|
| jump-grip-depth | 1/5 · 1/5 | **5/5 · 5/5** | R6-CHECK 의무 계산의 직접 효과. 1차의 1건도 환각 임계값에 의한 요행이었음 |
| physical-rotation-invalid | 0/5 · 5/5 | 1/5 · 5/5 | |
| physical-negative-depth | 2/5 · 5/5 | 1/5 · 5/5 | |
| physical-2d-out-of-image | 0/5 · 5/5 | 1/5 · 5/5 | |
| consistency-translation-workspace | 0/5 · 5/5 | 0/5 · 5/5 | |
| consistency-grip-depth | 2/5 · 5/5 | 1/5 · **4/5** | 유일한 미탐 1건 (§5.4) |
| payload-drift | 5/5 | 5/5 | 코드 채널 (LLM 무관) |
| zod-reject ×2 | 5/5 | 5/5 | 코드 채널 |
| projection-map-failed | 5/5 | 5/5 | 코드 채널 |
| **오탐(정상 450건 중)** | **39건** | **0건** | 하드 네거티브 5/5 통과 포함 |

## 5. 분석

### 5.1 오탐 39 → 0: rule ID 인용 의무 + 화이트리스트 + 출력 앵커의 합작

1차 오탐의 주 패턴(참고용 분포 통계를 임계값으로 발명)은 "판정 근거는 rule ID 뿐"
이라는 화이트리스트와 부등호 재확인 의무로 차단됐다. 잔여 출구였던 서술형 시작
오탐("R1 위반 — …"으로 운을 떼고 근거를 지어내는 패턴)은 반복 루프 대응으로 넣은
출력 앵커(§5.3)가 함께 봉쇄했다 — 중간 라운드에서 관찰된 필드 오독 오탐(x 좌표
음수값을 z 위반으로 인용, 배치에 없는 scene 지목)도 최종 실행에서는 소멸했다.

### 5.2 jump 1→5 (strict까지 만점): 산수를 토큰으로

"검사는 조용히"라는 전역 억제에 R6 만 예외를 열어 **계산 라인을 강제**한 것이
결정적이었다. LLM 은 토큰을 생성하면서 계산하므로, 경계선 비교(Δ=0.110 vs 0.10)는
암산 지시로는 실패하고 서면 계산 지시로는 성공한다. 프리플라이트 재현에서 1차 미탐
윈도우(01302~01305 쌍 4개)가 정확한 산수와 함께 4/4 탐지됐고 본 실행에서도 재현됐다.

### 5.3 부작용과 처방의 연대기 — rule 엔지니어링 실증

룰북 v1 → v2 사이에 관찰된 실패 모드들은 "rule 문서로 소형 모델을 조정"할 때의
일반적 함정으로, 논문의 정성 분석 재료다:

| 실패 모드 | 증상 (실측) | 처방 |
|---|---|---|
| 절차 서술 유도 | "판정 절차" 항목이 규칙별 수행 나열을 유도 → 통과 서술로 4096 토큰 잘림, JSON 미도달 | "통과 서술 전면 금지, R1~R5 산문 0줄" 명시 |
| 체인 비교 | 서로 다른 scene 인접 레코드를 연쇄 비교(R6 오적용) | "sceneKey 완전 일치 쌍만 + 교차 Δ>0.10 도 위반 아님" 이중 게이트 (부정 예시 포함) |
| **결정론적 반복 루프** | 특정 정상 배치에서 "레코드 N: gripSucceed=1 이나" 를 가공의 레코드 298번까지 반복, 4095tok/288초 소진. temperature 0 이라 재시도마다 동일 재현 → 관찰 루프 영구 정체. frequency_penalty 0.3 무효(반복 구절의 숫자가 계속 바뀌어 토큰 페널티 회피) | **출력 시작 앵커**: 응답 첫 글자를 R6-CHECK 또는 \`\`\`json 으로 강제 — 루프의 진입점(서술형 문장 시작) 자체를 봉쇄. 51.7초/295tok 정상 완료로 회복 |
| 필드 오독 | x 좌표(음수 정상)를 z 깊이 위반으로 인용 | R5 에 "각 축은 자기 범위와만 비교" 명시 + 앵커의 부수 효과로 소멸 |

### 5.4 잔여 한계

1. **strict 지목은 여전히 부분적** (센서 6종 9/30). 이상 클러스터 윈도우에는 위반
   레코드가 5개씩 몰려 있는데 모델은 대표 1~2개만 지목한다. loose(윈도우 단위)로는
   29/30 이므로, 층1의 역할(경보)로는 충분하나 scene 단위 귀속이 필요하면 배치
   축소(8→4) 또는 "위반 레코드 전수 나열" 계약 강화가 후보다.
2. **단독 분리 레코드의 조용한 미탐 1건**: 01330(consistency-grip-depth)은 자기
   클러스터(01326~01329는 모두 탐지)에서 홀로 다음 윈도우로 쪼개졌고, 그 윈도우는
   정상 판정됐다. R5 단일 레코드 범위 검사의 암산 실패로, F1 과 같은 뿌리다 —
   R5 에도 계산 라인을 확장하면 잡히겠지만 출력 길이와의 트레이드오프가 있다.
3. **근거 서술의 수치 정확성은 미검증**: 본 평가는 triggered/scene 만 채점한다.
   판정 사유 텍스트의 인용 수치·부등호가 정확한지는 층2(문서 품질) 루브릭에서
   별도로 채점해야 한다(1차에서 "탐지는 맞고 근거는 틀린" 사례 다수 관찰).

### 5.5 후속 실험 — 지목 정밀도 개선 시도(룰북 v3)와 부정적 결과

§5.4-1 의 지목 한계를 겨냥해 룰북 v3 를 실험했다(2026-07-14, 결과:
`layer1-run-2026-07-14T01-27-*.json` 계열). 처치: **"위반을 하나 찾아도 멈추지 말고
8건 전부 검사, 위반 레코드마다 정확히 한 줄, 위반 요약 줄 수 = offendingSceneKeys
개수"** — R6-CHECK 가 jump 지목을 만점으로 만든 '레코드별 의무 라인' 원리를 위반
요약 전체로 확장한 것이다.

| 지표 | v2 | v3 | 해석 |
|---|---|---|---|
| Recall (loose) | 98% | **100%** | 유일 미탐(01330)까지 회수 |
| Recall (strict) | 58% | **72%** | 표적한 지목 개선은 실제로 달성 |
| **오탐율 FPR** | **0%** | **15.33% (69건)** | 정상 450건 중 69건 오경보 |
| **정밀도** | **100%** | **34.3%** | 경보 3건 중 2건이 거짓 |
| 하드 네거티브 | 5/5 | **1/5** | 함정 데이터 4건 오탐 |

**실패 메커니즘 — 지목 완전성 압박이 작화(confabulation)를 유도한다.** "전부
나열하라"는 지시가 소형 모델에게 '위반이 여러 개 존재할 것'이라는 암묵적 기대로
작동해, v2 가 "애매하면 정상"으로 유지하던 판정 균형을 무너뜨렸다. 오탐 사유를
보면 v1 에서 눌렀던 실패 모드들이 전부 재발한다: x 좌표(음수 정상)를 "R2 음수
깊이"로 오독, 거짓 부등호("Z=1.0205 > 1.15"), 임계값 발명("z1=0.139 < 0.15").
즉 **지목 재현율(strict)과 판정 정밀도(FPR)는 프롬프트 압박 한 축을 공유하는
트레이드오프**이며, 9B 모델에서 rule 문서만으로 둘을 동시에 얻을 수 없었다.

결정: **v2 유지**(경보 시스템은 정밀도가 우선 — FPR 15%는 운영 불가). v3 는
폐기하되, strict 개선은 프롬프트 압박이 아니라 §8 의 2-pass 지목(트리거된
윈도우에 한해 지목 전용 재질의) 또는 하이브리드의 결정론 귀속으로 달성해야
한다는 것이 본 실험의 교훈이다.

### 5.6 후속 실험 — 윈도우 축소(8→4)와 동거 효과의 발견

strict 개선의 두 번째 시도로 관찰 윈도우를 8→4 로 줄였다(룰북 v2 고정,
`SENSOR_OBSERVER_MAX_BATCH_SIZE=4`, 2026-07-14,
`layer1-run-2026-07-14T02-14-14-188Z.json`). 가설: 윈도우당 지목 후보가 절반이면
scene 귀속이 쉬워져 strict 가 오른다.

| 지표 | v2 @ 윈도우8 | v2 @ 윈도우4 |
|---|---|---|
| Recall (loose) | **98%** | 92% |
| Recall (strict) | 58% | 60% |
| 오탐율 FPR | 0% | 0.44% (2건) |
| 정밀도 | 100% | 93.8% |
| LLM 호출 수 | 61 | ~122 (2배) |

가설은 기각됐다 — strict 는 +2%p 에 그쳤고 **loose 가 98→92% 로 하락**했다.
하락의 전모는 physical-rotation-invalid 한 유형에 있다: loose 5/5 → **1/5**.

**동거 효과(co-tenancy)의 발견.** 윈도우8에서 rotation-invalid 5건(01306~01310)은
negative-depth 3건(01311~01313)과 같은 윈도우에 있었고, 그 윈도우의 트리거는
사실상 음수 깊이의 z 평균 급변이 견인했다 — rotation 파일들의 loose 성공은 R4
(회전행렬 검사)의 성과가 아니라 **강한 이웃 이상과의 동거 덕**이었던 것이다.
윈도우4에서 [01306~01309]가 독방이 되자 모델은 R4 산수를 스스로 해내야 했고,
1/5 만 잡았다. 즉:

1. **윈도우 크기는 strict 병목이 아니다** — 지목 흐림의 원인은 후보 수가 아니라
   모델의 조용한 산수·귀속 능력 자체다.
2. **loose 재현율의 일부는 "이상은 몰려온다"는 벤치마크 배치 특성에 기대고 있다.**
   윈도우가 클수록 약한 이상이 강한 이웃의 경보에 편승한다. 이는 llm-only 의 실질
   탐지력을 벤치마크가 다소 후하게 측정할 수 있다는 타당성 경고이자, 운영에서는
   "윈도우를 줄이면 경보가 정직해지는 대신 줄어든다"는 운영 노브의 성격 규정이다.

결정: **윈도우 8 유지**(loose 우선 + 호출 수 절반). strict 의 남은 경로는 2-pass
지목이다.

## 6. 방법론 노트 (재현 시 필수)

### 6.1 채점기 유니코드 정규화 버그 (수정됨)

macOS 파일명·DB·Kafka 메시지의 한글은 NFD(자모 분해)인데 **LLM 이 재생성한
`offendingSceneKeys` 는 NFC** 로 나온다(토크나이저 특성). 원문 문자열 비교는 항상
false 가 되어 strict recall 과 FPR 이 구조적으로 0 으로 집계됐다. 평가 러너에
`canonicalSceneKey()`(NFC 정규화)를 넣어 수정했으며, **1차 수치는 동일 실행 로그의
NFC 재채점 결과**(`…-rescored-nfc.txt`)다. 수정 전 러너가 출력한 1차 수치(strict
40%/FPR 0%)는 무효다.

### 6.2 실행 안정화 설정 (`.env`)

| 설정 | 값 | 이유 |
|---|---|---|
| `SENSOR_OBSERVER_ANALYSIS_DISABLED` | 1 | 에피소드 분석(35B)이 같은 LM Studio 를 점유해 관찰 타임아웃 유발 |
| `LLM_CONTEXT_ANALYSIS_DISABLED` | 1 | 로그 선판단 트리거 1건(404)이 35B 분석을 동기 실행, 서버 ~12분 점유 실측 |
| `SENSOR_OBSERVER_MAX_OUTPUT_TOKENS` | 4096 | R6-CHECK 포함 합법 출력 1~2k tok. 1024 는 연쇄 truncation 으로 실행 자체를 죽임 |
| `SENSOR_OBSERVER_LLM_TIMEOUT_MS` | 120000 | 행 걸린 호출을 빨리 실패시켜 재시도 예산을 정체 가드 안에 넣음 |
| `SENSOR_OBSERVER_MAX_FAILURE_STREAK` | 50 (평가 시) | LLM 서버 순단 중 배치가 폴백(=조용한 미탐)으로 소실되지 않게 requeue 보존. 운영 기본 3 |
| `PREJUDGE_MAX_OUTPUT_TOKENS` | 1024 | 선판단 장문 생성의 서버 점유 차단 (prejudge 에도 `reasoning_effort: none` 적용) |

관찰자 실패 로그는 error→info 로 낮췄다 — error 로그가 Kafka 로 재유입되어 선판단을
재트리거하는 피드백 루프 차단(`LLMContextService` 와 동일 사유).

### 6.3 재현 명령

```bash
# 전제: docker 스택(TimescaleDB·Kafka·fluent-bit) + LM Studio(qwen3.5-9b) 기동
npm run start   # .env 는 §6.2 값
EVAL_OBSERVE_TIMEOUT_MS=7200000 EVAL_OBSERVE_STAGNATION_MS=1500000 \
  node scripts/eval/run-layer1-detection.mjs
```

1차(순수 LLM) 조건 재현은 룰북 주입 커밋 이전 프롬프트로 되돌려 같은 명령을 실행한다.
연속 실행 사이에는 이전 실행의 미소비 Kafka 메시지를 비워야 한다(consumer group
`sensor-value-observer`·`llm-context-builder` 오프셋을 latest 로 리셋).

## 7. 논문 관점 정리

1. **주장 가능한 결과**: 동일 소형 모델(9B)에서 도메인 rule 문서 주입만으로 층1
   탐지가 loose 92→98%, strict 50→58%, FPR 8.67→0%, 정밀도 39→100%로 개선됐다.
   특히 "임계값을 명시한 rule + 계산 라인 의무화 + 출력 계약"의 조합은 소형 모델의
   3대 실패 모드(산수 회피·임계값 환각·귀속 흐림)를 각각 겨냥해 효과가 분해된다.
2. **rule 문서의 운영적 가치**: 룰북은 코드가 아닌 마크다운이라 도메인 전문가가
   직접 갱신 가능하며, 본 실험에서도 재빌드 없이 v1→v2 반복이 이뤄졌다. 이는
   Self-Adaptive CQRS 의 "LLM 에 무엇을 컨텍스트로 주입하는가"라는 연구 질문에서
   컨텍스트의 한 축(도메인 판정 규칙)을 실증한다.
3. **한계 고지**: llm-only 는 ablation 조건이다. 본 시스템의 기본 설계(hybrid —
   결정론 4층 주석 + LLM 해석)와의 비교가 다음 실험이며, rule 주입 llm-only 가
   hybrid 에 얼마나 근접하는지가 "LLM 판정 권한의 적정 범위" 논증의 근거가 된다.
