## 5. 부정적 발견 — R4(회전행렬)는 llm-only 사각지대

A7 의 초안은 R4(회전행렬 유효성) 위반이었으나, llm-only 9B 가 **반사행렬(det=−1)·
영행렬(det=0)·스케일 ×10** 을 전부 정상 판정했다(스모크 2회 실측, `sensor.observe.skipped`,
증거: `results/layer2-docs-llm-only-20x5-archive/`). 원인은 룰북 설계에 있다 —
R4 는 유일하게 CHECK 서면화 없이 "조용히 검사 + 확신 없으면 판정 금지"로 남은 암산
룰이라, 소형 모델이 규칙 문구를 알아도 발동시키지 못한다. §9-1 의 "암산 검사는 실패한다"
교훈(A4 전량 미탐 → v4.0 CHECK 서면화)의 재확인이며, **결정론 주석이 있는 hybrid 의
필요성을 뒷받침하는 추가 근거**다. R4 실측은 hybrid 조건의 후속 과제로 남긴다.

- **인프라 장애와 회수**: 수집 기간 중 LLM 서버(Mac Studio) 간헐 정체로 1차 수집에서

  (10런 재수집, 1런 잔존) → 3차(1런) 로 **100/100 완주**. 모든 실패는 트리거 이후
  분석 LLM 호출 타임아웃(`Request timed out`)이었고 탐지 실패·오탐은 없었다.
  실패 런은 run-meta 가 남아 이어하기가 건너뛰므로, **타임아웃 런 삭제 후 재실행**이
  회수 절차다(래퍼 `run-wrapper.sh` 3b 참조).
- **스모크 게이트**: 리스크 큰 신규 시나리오(B2·A7·A8·E4) × rep-1 을 먼저 돌려 실패 시
  전체 중단하는 게이트가 A7 초안의 R4 사각지대를 캠페인 진입 전에 3회 잡아냈다
  (게이트 비용 ~1.5시간 vs 방지한 낭비 40시간+).
- **해석 주의**: §9 와 동일하게 "llm-only 탐지 + 주석 컨텍스트 분석" 조건이다(완전한
  llm-only 아님). 분석 모델은 §9 의 35B 가 아니라 **27B(coder-mtp)** 로 바뀌었으므로
  §9 표와 직접 비교할 때는 모델 차이를 병기할 것.

## 7. 후속 과제

1. **한자 혼입 후처리** — 유일한 문서 감점원(13건). invokeNode 공통 관문의 재질의가
   소진된 뒤에도 잔존하므로, 결정론 치환(한자→한글) 최종 패스 추가 검토.
2. **SQL 타입 오탈자 정규화** — `doubleprecision` 계열 8건. sql-validator 에서 치환 후
   재검증하면 SQL 실행률 96% → ~99.6% 예상.
3. **격리 순서 검증기** — "정리 SQL 이 제약 추가보다 선행"을 결정론 체크로 강제(1건).
4. **R4 hybrid 실측** — §5 의 사각지대를 결정론 주석 병합 조건에서 재평가.
5. **층3 루브릭 채점** — 본 수집물 100건을 층3(내용 품질 LLM 채점)의 입력으로 사용.
