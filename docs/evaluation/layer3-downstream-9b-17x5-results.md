# 층3 다운스트림 효과 본평가 결과 — 17종 × k5, 9B 소비자 (2026-09-11)

> `docs/evaluation/performance-evaluation-plan.md` 층 3(다운스트림 효과)의 첫 본평가.
> 질문: **생성된 Docs가 Local LLM의 Read Model 재생성 작업을 실제로 돕는가?**
> 입력: 층2 v2 수집물(`scripts/eval/results/layer2-docs-llm-only-20x5-v2/`) 17종 × 5 rep.
> 산출물: `scripts/eval/results/layer3-downstream-9b-17x5/` (답변 664건, 컨텍스트 166건, 자동 채점·judge JSON, `verify-summary.md`, `judge-summary.md`).

## 1. 한 줄 요약

**같은 9B 로컬 모델에 Docs를 주면, 로그+스키마만 줄 때보다 실행 가능한 해결 SQL 통과율이 37% → 84%로 오르고(McNemar p < 10⁻⁷), judge 4축 전부에서 유의하게 높다.** 이득은 로그·센서 채널에서 나오며, 질의(E) 채널에서는 Docs의 `doublePrecision` 오탈자가 그대로 전파되어 실행 지표상 이득을 상쇄한다 — **Docs 품질이 다운스트림의 상한**임을 정량적으로 확인했다.

## 5. 해석

1. **Docs의 기여는 "판단의 이전"이다.** 진단(T1, judge 진단축)은 두 조건이 거의 같다 — 9B도 로그를 보면 무엇이 문제인지는 안다. 갈리는 것은 그다음이다: 어떤 테이블을 어떤 컬럼으로 만들지, 기존 v1 자산을 건드리지 않고 어떻게 전환할지. 로그+스키마 조건은 존재하지 않는 컬럼을 참조하거나(18건), 기존 테이블에 ALTER를 걸거나(4건), 자료에 없는 값을 채운 INSERT를 지어냈고(judge unsupportedClaims 1.86건/단위), Docs 조건은 그 판단을 Docs에서 받아 실행 가능한 산출물로 옮겼다.
2. **센서 채널이 Docs의 존재 이유를 가장 잘 보여준다.** 로그 표만으로는 z 평균·Δ·워크스페이스 위반 같은 파생 지표를 어떻게 계산할지 알 수 없어 로그+스키마 조건은 24건 전부 T2에 실패했고 호환 절차 점수도 1.00이다. Docs는 계산 명세(투영 매핑)를 함께 주므로 23/24가 통과했다.
3. **질의 채널은 Docs 품질이 상한이다.** 집계·조인 테이블은 9B가 스키마만으로도 만들 수 있어 베이스라인이 17/25를 통과했고, Docs 조건의 실패 8건은 전부 Docs의 `doublePrecision` 오탈자를 베낀 것이다. judge SQL 축은 여전히 Docs가 높지만(4.80 vs 3.80), 실행 지표에서는 무승부다. 층2 결과 문서 후속 과제 2번(sql-validator 타입 정규화)의 필요성을 층3 수치로 뒷받침한다.
4. **비용.** Docs 조건의 입력 토큰은 단위당 46K로 로그+스키마(26K)의 1.8배이지만, 출력 토큰은 3.0K vs 5.0K로 더 적고 지연도 99초 vs 115초로 짧다. 9B가 Docs가 없으면 더 길게 헤매다 더 자주 반복 루프에 빠진다(잘림 7 vs 15).

## 6. 한계 (논문 서술 시 병기)

- **judge 모델**: Anthropic/OpenAI 키 부재로 로컬 35B(qwen3.6)를 썼다. 소비자(9B)·Docs 생성(27B)과는 다른 모델이지만 같은 qwen 계열이다. 응답이 전부 저장돼 있으므로 외부 강모델로 재채점 가능. 30% 사람 채점 κ는 아직 미수행.
- **판단 앵커·체크리스트(T1·T4)는 변별력이 없다.** 자동 지표는 T2·T3(실행)만 결론에 쓰고 T1·T4는 judge로 대체한다.
- **B2 시나리오**의 로그+스키마 조건 T3 4/4 통과는 파생 질문이 기존 `read_multimodal`만으로 답할 수 있는 형태여서 생긴 것이다(문항 설계 한계).
- **소비자 9B 반복 루프**(잘림 22건)는 모델 특성이며 양 조건에 모두 나타났다. 채점상 실패로 처리했다.
- **선행 파일럿과의 차이**: 파일럿(5종 rep-1, max_tokens 4096)은 본평가에서 새 설정으로 재실행되어 본 표에는 포함되지 않는다.
- **캠페인 중 정정**: 최초 실행에서 다중 Docs rep의 첫 문서를 채택하는 규칙이 A9·A10·B2의 12 단위에 센서 관찰기의 부수 문서를 골랐다. 채널 일치 규칙으로 고쳐 해당 12 단위만 재실행했고, 나머지 71 단위는 같은 문서가 선택됨을 확인했다.

## 7. 후속 과제

1. 외부 강모델 judge 재채점 + 30% 사람 채점으로 Cohen's κ 산출.
2. Docs 타입 오탈자 정규화(층2 후속 과제 2번) 적용 후 질의 채널 재평가 — 상한 상승 폭 측정.
3. 27B 소비자로 동일 입력 재실행 — 모델 크기가 커져도 Docs 효과가 유지되는지.
4. Ablation A′(Docs에서 로그·스키마 블록 제거) — Docs 이득의 원천이 LLM 판단인지 확인.
5. 대조군(F2·F3·F5) 로그+스키마 조건으로 다운스트림 오탐(없는 문제를 만들어 내는지) 측정.
