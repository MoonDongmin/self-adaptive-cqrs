# 제 1 장 서론

로봇이 물건을 집는 파지 작업을 수행하는 Physical AI 환경에서는 시도 한 번마다 관절 센서 값, 카메라 영상, 파지 성공 여부와 같은 데이터가 실시간으로 유입된다. 이러한 데이터를 최종 상태만 덮어쓰는 방식으로 저장하면 각 시점의 로봇의 행동과 변화 이력이 사라져, 새로운 분석·학습 요구가 생길 때마다 데이터를 다시 수집해야 한다. 이벤트 소싱(Event Sourcing)은 이 문제를 해결하기 위해 시스템에서 일어난 모든 사건을 불변 이벤트로 기록하고, 현재 상태는 이벤트의 재생을 통해 도출하는 데이터 관리 기법이다[1]. 이벤트 소싱은 쓰기와 읽기의 책임을 분리하는 CQRS(Command Query Responsibility Segregation) 패턴과 함께 사용되는 경우가 많다[2, 3]. 이 구조에서 쓰기 측은 발생한 모든 이벤트를 원본 그대로 보관하는 저장소(Event Store)가 되고, 조회 측에는 조회 목적별로 이벤트를 미리 구체화(materialization)해 둔 조회 전용 데이터 모델, 즉 Read Model이 놓인다. 그 결과 전체 이력이 보존되면서도 빠른 조회가 가능하며, 축적된 이벤트로부터 새로운 조회용 Read Model을 언제든 다시 구성할 수 있다[2, 4, 5].

그러나 Read Model의 유지에는 상당한 관리 비용이 따른다. Read Model은 조회 요구가 바뀔 때마다 함께 바뀌어야 하며, 실무자 대상 실증 연구들도 스키마 진화와 프로젝션(projection, 이벤트를 Read Model에 반영하는 처리) 재구축을 이벤트 소싱 운영의 핵심 난제로 지목한다[6, 7]. 예를 들어, 로봇에 새로운 센서가 추가되어 스키마에 정의되지 않은 필드가 이벤트에 유입되거나, 기존 Read Model로 답할 수 없는 조회 요구가 생기면 개발자가 직접 요구를 해석하고 새 Read Model의 스키마를 설계하며, 테이블을 생성하는 DDL(Data Definition Language)과 프로젝션 로직, API 버전 변경까지 관리하여야 한다. 이러한 수작업 대응은 가파른 학습 곡선을 갖는 이벤트 소싱 아키텍처의 특성상 전문성을 갖춘 개발자에 의존하며[7], 요구가 발생한 시점부터 반영되기까지의 지연으로 인해 조회 계층이 변화를 즉시 수용하지 못한다. 본 논문에서는 이러한 문제를 Read Model의 수동 스키마 진화(manual schema evolution) 문제로 정의하고, 그 완화를 연구 목표로 설정한다. 기존의 스키마 진화 연구는 이벤트 스키마의 버전 관리와 변환 기법에 집중되어 있고[7], 데이터베이스 자동화 연구는 인덱스 선택과 같은 물리적 설계에 초점을 두고 있어[8], 어떤 Read Model을 새로 만들어야 하는가에 해당하는 설계 의사결정은 연구의 공백으로 남아 있다.

이 문제의 본질은 운영 중에 발생하는 변화의 감지와 대응이 모두 사람에게 맡겨져 있다는 점이다. 시스템이 스스로를 관측(Monitor)·분석(Analyze)·계획(Plan)·실행(Execute)하며 변화에 대응하도록 하는 접근은 자가 적응 시스템(Self-Adaptive Systems) 분야에서 MAPE-K 피드백 루프로 체계화되어 왔다[9-12]. 그러나 전통적인 자가 적응 기법은 설계 시점에 미리 정의된 적응 행동을 선택·실행하는 데 초점을 두므로, 새로운 스키마를 설계하고 SQL을 작성하는 것과 같이 도메인 이해와 생성 능력이 필요한 적응까지 다루기는 어려웠다. 최근 LLM(Large Language Model)이 자연어 요구로부터 코드를 생성하고[13] 데이터베이스 스키마를 근거로 실행 가능한 SQL을 생성하는 능력[14-17], 그리고 시스템 로그를 해석하고 이상을 탐지하는 능력[18-21]을 보이면서, LLM을 MAPE-K 루프에 통합하여 이러한 한계를 넘어서려는 시도가 등장하고 있다[22-24]. 그러나 이러한 접근을 이벤트 소싱·CQRS의 Read Model 수명주기에 적용하려는 연구는 아직 미흡한 실정이다.

본 논문에서는 기존 이벤트 소싱·CQRS 구조에 LLM 기반 분석 영역을 결합한 Self-Adaptive CQRS 아키텍처를 제안한다. 제안 시스템은 개발자가 남기는 구조화된 로그와, 시스템이 보유한 Read Model·이벤트의 스키마와 의미를 카드 형태로 관리하는 Insight Read DB의 두 가지 소스로 LLM 컨텍스트를 구성한다. 유입되는 이상 신호는 소형 LLM이 1차 선별하고, 선별된 신호만 진단 에이전트가 추론과 도구 호출을 반복하는 ReAct 방식[25]으로 로그 데이터베이스, Insight Read DB, 소스 코드를 직접 조회하며 근본원인을 분석한다. 최종 산출물은 단일 문서이며, 어떤 Read Model을 왜 재생성해야 하는지에 대한 권고 문서, 해당 Read Model을 재생성하는 DDL, Read Model 교체에 따른 API Versioning 전략의 세 요소를 항상 함께 담는다. 생성된 DDL은 사람의 승인을 거쳐 적용되고, 신규 Read Model의 스키마 카드는 Insight Read DB에 등록되어 다음 분석의 컨텍스트로 순환한다. 전체 루프는 MAPE-K 참조 모델의 각 단계에 대응되며, 데이터를 외부로 전송할 수 없는 제조 환경의 제약을 고려하여 전 과정은 외부 API가 아닌 로컬 LLM으로 구동된다. 제안 시스템은 실제 구현을 통해 이상 탐지 정확도와 산출 문서의 품질을 포함한 다층 평가로 그 실효성을 검증하였다.

본 논문의 구성은 다음과 같다. 제 2 장에서는 이벤트 소싱과 CQRS, Read Model 수명주기와 스키마 진화, 자가 적응 시스템과 MAPE-K, LLM 기반 코드 생성과 Text-to-SQL의 네 영역에서 관련 연구를 검토한다. 제 3 장에서는 제안 시스템의 설계와 구현을 기술하고, MAPE-K 관점에서 자가 적응 루프를 분석한다. 제 4 장에서는 평가 목표와 실험 환경, 평가 지표를 정의하고 실험 결과를 분석한다. 마지막으로 제 5 장에서는 결론과 향후 연구 방향을 제시한다.
