# 구현 가이드 — 센서 값 이상 관찰자(Sensor-Value Anomaly Observer)

> **목적.** Event Store→Read Model 적재 과정에서 "스키마엔 맞지만 물리적으로 비정상인 센서 값"을 LLM이 판별해 권고문서(Docs)를 생성하는 경로를 신설한다. HTTP 로그 경로는 이미 존재하므로 건드리지 않는다. 본 문서는 **그대로 따라 구현 가능한 단계별 가이드**다(소스는 아직 미수정 — 이 문서는 구현 지침).
>
> **선행 문서.** [`이상값-판정-로직-갭분석.md`](./이상값-판정-로직-갭분석.md) (§6 결정 확정, §8 열린 질문)의 후속 구현 계획.

---

## 0. 배경 요약 (왜 / 무엇이 없는가)

- 흐름: 인입 → `event_store`(append-only) → `CatchUpRunner` 프로젝션 → `read_grip_result`.
- 검사는 **구조적 zod(`toyDataSchema.parse`) + 빈 `objects` 검사**뿐. 이미지 밖 `grip_2d_pose`, 작업영역 밖 `robot_tf.translation`, 비물리적 `grip_3d_pose` 같은 값은 **에러 없이 통과** → `read_grip_result` 오염 → **에러 로그가 없어 기존 `prejudge`도 발동 안 함**(= 침묵 실패).
- 기존 로그 라인: `pino→Kafka 'log-events'→LogConsumer→prejudge→LLMContextService.analyze→analysis.graph→analysis-{id}.md`. **이 구조를 센서용으로 미러링**한다.
- 사용자 결정: **D1** 인라인 금지, Kafka로 디커플링 + 작은 배치 / **D2** 기존 LangGraph 재사용 + 리서치 반영 Docs / **D3** payload 전체 수기 베이스라인 런타임 주입, LLM 직접 판정.
- **D3 보강(2026-07-07).** min/max 베이스라인만으로는 (i) 범위 안이지만 통계적으로 벗어난 값, (ii) 열 노름=1이나 직교가 아닌 가짜 회전행렬을 원리적으로 못 잡는다. 그래서 **결정론적 통계 주석 레이어**를 배치 렌더링 앞에 추가했다: 코드가 robust-z(최근접 관측 클러스터 envelope 기반)와 회전행렬 항등식(R·Rᵀ=I, det=+1)을 계산해 걸린 레코드에만 `⚠ stat` 근거 라인을 붙이고(`renderAnnotatedSensorBatch`), **LLM은 그 수치를 근거로 최종 판정**한다. 산수는 코드가, 해석·triggered 판정은 여전히 LLM이 한다(§Phase A 보강 참조). 이는 D3의 "값이 레코드를 걸러내는 수치 **필터**는 없다"는 원칙과 충돌하지 않는다 — 통계는 게이트가 아니라 **증거로 첨부**될 뿐이다.

**불변식(반드시 지킬 것):** `any` 금지(`unknown`+가드/zod/제네릭), 식별자 전체 단어(`id/url/api/db/json/http/dto/cqrs/es/llm`, `i/j/k` 예외), catch 변수 `error`, `event_store` 절대 변형 금지(격리/수정은 read 측만), 코드/SQL 필드 안 마크다운 펜스 금지(render가 이미 감쌈).

## 1. 구현 순서 개요 (각 단계는 독립 컴파일·검증 가능)

```
Phase A  타입·설정·베이스라인 스캐폴딩            → tsc 통과
Phase B  프로젝션 → Kafka 발행                     → 토픽에 메시지 보임
Phase C  컨슈머 + 관찰자(LLM 직접 판정) 루프        → triggered 로그
Phase D  그래프 수렴(state/nodes/graph/output type) → 기존 로그 경로 무회귀
Phase E  Docs 노드 + grounding 사후검증 + 프롬프트   → dq-{scene}.md 생성
Phase F  모듈 와이어링                              → 부팅 OK
Phase G  end-to-end 검증                            → 3요소 Docs 확인
```

## Phase A 보강 — 결정론적 통계 주석 레이어 (2026-07-07)

> **왜.** min/max 베이스라인은 정보량이 0차(support)뿐이라 (i) 범위 안 통계적 이상치, (ii) 열 노름=1이나 비직교인 가짜 회전행렬을 못 잡는다. 이 두 부류를 **코드가 결정론적으로 계산**해 배치에 근거로 첨부하고, 판정은 LLM이 유지한다. 산출 코퍼스 139건의 z는 정의상 전부 0 → **정상 코퍼스 오탐 없음**.

### A-6. `src/sensor-observer/sensor-value-statistics.ts` (신설)
toy-data 139건에서 산출한 차원별 분포 통계와 두 순수 함수.
- `robustZ(value, statistics)` — **최근접 관측 클러스터 envelope 기반** robust-z. 로봇이 소수의 고정 마운트에서 촬영해 translation이 이산 클러스터(x 3개, y 2개)를 이루므로 단일 median z-score는 정상 클러스터를 오탐한다. 따라서 envelope `[low, high]` 안이면 z=0, 밖이면 `0.6745 × (envelope까지 거리) / max(클러스터 MAD, scaleFloor)`. 임계 `ROBUST_Z_THRESHOLD = 3.5`.
- `checkRotationMatrix(rotation)` — 회전행렬 항등식. 열 노름 검사만으로는 부족(열 노름이 전부 1이어도 비직교/반사행렬일 수 있음)하므로 `R·Rᵀ = I`(직교성)와 `det(R) = +1`(반사 아님)을 `ROTATION_TOLERANCE = 0.01`로 검사.

### A-7. `src/sensor-observer/sensor-batch-annotator.ts` (신설 — `renderSensorBatch` 대체)
`renderAnnotatedSensorBatch(batch)`: 레코드 JSON 라인은 **손실 없이 그대로**(observedValue verbatim substring 검증 원천) 두고, 통계 검사에 걸린 레코드 **바로 아래에만** `⚠ stat [{sceneKey}#{attempt}] …` 근거 라인을 붙인다. `robotTf`/`grip3dPose`는 `unknown`이므로 타입 가드(`isRecord`/`asFiniteNumberArray`)로 안전 추출 — 형태가 다르면 크래시 없이 판정 skip.

배치 렌더링 사용처(`sensor-screener.ts`, `sensor-observer.service.ts`의 `batchText`)를 모두 `renderAnnotatedSensorBatch`로 교체했고, 관찰자 프롬프트에 규칙 1-1(⚠ stat은 코드가 계산한 결정론적 근거이니 재계산 말고 reason에 수치 인용)을 추가했다.

**✅ 검증 A(보강):** `sensor-batch-annotator.spec.ts` 10건 — 범위 안 이상치(y=0.93 → robust-z 초과)·비직교 회전행렬·반사행렬·grip 깊이 음수·형태 미상 payload skip·정상 verbatim 보존. 실제 fixture `ANOMALY_CR99_transZ`(z=5.0) → `robotTfTranslationZ=5 robust-z=612.8` 플래그 확인.

const rows: Insert[] = [];
await this.db.transaction(async (tx) => {
  for (const event of events) {
    const row: Insert = projector.map(event);
    await projector.upsert(tx, row);
    rows.push(row);
  }
  await this.cursors.update(tx, projector.name, batchTo);

    if (messages.length > 0) await this.sensorPublisher.publish(messages);

### C-2. `src/sensor-observer/sensor-observer.prompt.ts` (신설) — `SENSOR_OBSERVER_PROMPT`
센서 값 관찰자 시스템 프롬프트(갭 §6-2: 직접 판정). 지시:
1. 기대범위 출처는 **두 가지**: 주입된 D3 베이스라인 규칙, 그리고 배치 안 `⚠ stat` 주석 — 그 외 숫자 발명 금지, 규칙 없는 차원은 판정 안 함.
1-1. `⚠ stat` 주석은 코드가 결정론적으로 계산한 통계 근거(robust-z, 회전행렬 항등식)다. **재계산하지 말고 신뢰**하며, min/max 안이어도 robust-z가 크면 이상, 회전행렬 항등식 위반은 그 자체로 이상 확정. ⚠ 붙은 레코드는 반드시 짚고 z·편차 수치를 reason에 인용.
2. 각 차원: (a) 관측값 verbatim 인용 → (b) 베이스라인 기대범위/⚠ stat → (c) 수치 델타 → (d) 한 줄 해석.
3. 출력 = `{ triggered:boolean, reason:string, offendingSceneKeys:string[] }`(배치의 실제 sceneKey ⊆). 자유 추론 후 마지막에 JSON 펜스(prejudge 컨벤션).

## Phase E — Docs 노드 + grounding 사후검증 + 프롬프트

### E-1. `src/analysis/nodes/data-quality.node.ts` (신설)
`recommendation-docs.node.ts` 미러. facts는 **가장 구체적 근거 먼저**: `renderSensorFinding` → `renderRootCause` → `insightCards` → 베이스라인 → `await readSourceExamples()`.
```ts
export async function dataQualityNode(state) {
  try {
    const facts = [
      renderSensorFinding(state.sensorFinding!), '',
      renderRootCause(state.rootCause!), '',
      '## 도메인 스키마 (Insight Read DB)', state.insightCards, '',
      state.sensorFinding!.baselineText, '',
      await readSourceExamples(),
    ].join('\n');
    const output = await invokeNode(DATA_QUALITY_PROMPT, facts, dataQualityRecommendationOutputSchema);
    // ── 사후검증: observedValue 가 facts substring 인지 (환각 값 strip) ──
    const grounded = {
      ...output,
      sensorEvidence: output.sensorEvidence.filter((item) => facts.includes(item.observedValue)),
    };
    if (grounded.sensorEvidence.length !== output.sensorEvidence.length) {
      logger.warn({ action: LogAction.SENSOR_DQ_DONE,
        [LogContext.COUNT]: output.sensorEvidence.length - grounded.sensorEvidence.length },
        '근거 observedValue 가 배치 텍스트에 없어 제거');
    }
    return { outputs: { dataQualityRecommendation: grounded } };
  } catch (error) {
    return { outputs: {} };   // 기존 생성기와 동일: 실패가 co-select된 출력 머지를 깨지 않음
  }
}
```

### E-2. `DATA_QUALITY_PROMPT` (E-1 또는 prompts/index.ts) — 리서치 반영

## Docs 구조 근거 (웹 리서치 반영 — D2)

생성 Docs는 데이터 관측 플랫폼(Monte Carlo/Great Expectations/Soda/dbt 계약) + ADR/RFC/권고보고서 베스트프랙티스를 결합한 **incident-card** 구조다. 핵심 원리:

- **스키마 필드 순서 = 섹션 순서 = 환각 방지 1차 메커니즘.** LLM은 좌→우 생성이므로 `sensorEvidence`가 권고보다 앞서야 "근거 후 결론"이 강제된다(Tam et al., EMNLP 2024).
- **expectation-vs-actual 델타를 리드로.** 관측값 + 위반 베이스라인 규칙 + 수치 델타 튜플(GX/Soda 패턴).
- **심각도 3축**(영향 컬럼/행수/복구가능성) — 델타 크기 단독 금지(GX Cloud / Conduktor).
- **3-lane 근본원인 + Five-Whys** — 막연한 산문 대신 고정 분류 택1, 시스템적 갭까지(Monte Carlo RCA).
- **contain→fix→harden 3단계 복구** — 마지막 harden이 위반 차원을 베이스라인 규칙으로 계약화해 재발을 구조적으로 차단(Conduktor / Vimeo·Monte Carlo).
- **read model 진화는 "new table, replay, switch, archive"** — ALTER 금지, `read_grip_result_v2` 버전 접미사 + blue-green + API `/v2` 동반(Dennis Doomen / Marten / Oskar Dudycz / Azure CQRS).
- **코드 레벨 substring 사후검증** — 구조적으로 valid한 JSON도 환각 값 가능 → `observedValue`가 배치 텍스트 substring인지 검사해 strip(prejudge 사후검증 패턴 / Parasoft).
