# Stage 2 분석 파이프라인 — 멀티에이전트(LangGraph) 상세 구현

> **문서 성격**: 상세 구현 문서. "선판단이 **비정상**을 잡은 뒤, 여러 LLM이 **역할을 나눠** 근본원인을 분석하고 Insight Read DB를
> 대조해 **1~3개의 권고 출력**을 만들어 **추합**한다"의 파일별 완전 코드 청사진이다.
> **작성 기준**: `CLAUDE.md` 연구 다이제스트 + 짝 문서 `docs/llm-context/llm-context-빌더-구현계획.md`(이하 *빌더 문서*) + 본 라운드 설계 대화 + **디스크의 부분 구현**(`src/analysis/*`).
> **빌더 문서와의 관계**: 빌더 문서 §판정 메커니즘 **(4) langchain 심층 분석 LLM**(line 201–216)은 "단일 분석 LLM이 3출력 중
> **택1**"였다. 본 문서는 그 (4)를 **대체·정밀화**한다 — 단일 LLM·택1을 **역할 분담된 다중 에이전트 + 1~3개 출력 + 추합**으로 바꾼다.

## Context

선판단(Stage 1)은 이미 동작한다. `prejudge(batch)`(`src/llm-context/screener/prejudge.ts`)가 드레인 배치를 싼 모델(`qwen3-8b`)로
훑어 `PrejudgeChecked { triggered, reason, tripCorrelationIds }`를 내고, `src/llm-context/llm-context.service.ts:87`이
`"선판단: 비정상" / "선판단: 정상"`을 로깅한다. 바로 그 아래 한 줄이 비어 있다:

```ts
// src/llm-context/llm-context.service.ts:90
// TODO(다음 라운드): triggered면 ±N 윈도우 조립 → 컨텍스트 .md → 분석 LLM(3출력)
```

**본 문서가 채우는 것이 이 TODO다.** 네 종류의 역할 LLM이 협업하는 파이프라인으로 정밀화한다:

1. **근본원인 분석(RootCause)** — "선판단: 비정상"이 가리킨 트립 지점 **위아래 ±N줄**을 뽑아, 추론이 좋은 14B 모델에게 **"왜 이 오류가 났는가"** 를 묻는다.
2. **의사결정(Decision)** — 근본원인 + **Insight Read DB**를 대조해, 3출력 중 **1·2·3개**(또는 0개)가 필요한지 고른다.
3. **출력 생성(Generators)** — 고른 것만 각자의 역할 LLM이 만든다(① 버전 교체 / ② 권고 문서 / ③ 신규 Read Model).
4. **추합(Aggregate)** — 만들어진 1~3개를 하나의 권고 리포트로 통합한다.

이 "각 LLM에 역할 부여 → 조건부 분기 → 추합"을 **LangChain의 멀티에이전트 프레임워크 LangGraph**(`StateGraph`)로 오케스트레이션한다.

### 확정된 설계 결정

| 항목 | 결정 | 근거 |
| --- | --- | --- |
| 오케스트레이션 | **LangGraph `StateGraph`** (`@langchain/langgraph`) | 역할=노드, 조건부 1~3 fan-out + 추합 join을 상태 그래프로 명시 |
| Stage 2 모델 | **14B급 로컬 추론 모델**, `ANALYSIS_MODEL=qwen/qwen3-14b` | 선판단(8B)은 *선별*, 분석은 *추론*. baseURL/apiKey는 Stage 1과 공유 |
| 출력 개수 | ①②③ 중 **1~3개** 선택. **0개(조치 불필요)** 허용 | 0개는 선판단 false positive 흡수 안전판 |
| ±N 윈도우 | `log_event` 하이퍼테이블 질의, **트레이스 우선 + ±20행 패딩** | DeepLog(단일 줄 무의미 → 윈도우). 아래 §윈도우 길이 근거 |

```
[Stage 1] prejudge ──▶ triggered=true ("선판단: 비정상") + tripCorrelationIds
   │
   │ (코드: LogWindowRepository — LLM 아님)
   ▼

   │  + InsightService.renderAllCards()   ← §1 도메인 스키마 grounding(항상)
   ▼
   ┌──────────────────────── LangGraph StateGraph (src/analysis) ──────────────┐
   │ [1] RootCause 분석가 LLM   → 시간순 재구성 · 실패한 요청 의도 · 의심되는 Read Model 부족 │
   │        ▼                                                                              │
   │ [2] Decision 의사결정자 LLM → 근본원인 + Insight 카드 → ①②③ 중 1~3개 선택(+근거)         │
   │        │  addConditionalEdges (조건부 fan-out)                                          │
   │        ├──▶ ① genVersionSwitch ─┐                                                      │
   │        ├──▶ ② genRecommendationDocs ┤  (선택된 것만 병렬 실행)                            │
   │        └──▶ ③ genNewReadModel ──┤                                                      │
   │                                  ▼ (join)                                              │
   │ [4] aggregate 추합자 LLM   → 1~3개 출력 → 하나의 권고 리포트(우선순위·의존성·실행순서)       │
   └───────────────────────────────────┬──────────────────────────────────────────────────┘
                                        ▼
                          analysis-<correlationId|timestamp>.md 저장 + 로깅
```

- **경계**: **코드 = (0) 윈도우 추출 + 빈도 카운팅**, **LLM = (1)~(4) 역할별 4종 에이전트**.
- LangGraph **노드는 NestJS provider가 아니라 순수 함수**다. 의존성(LLM 설정)은 모듈 상수 `ANALYSIS_CONFIG`로 주입하고, 사실(윈도우·카드)은 **state로 전달**한다. DB 질의(윈도우)·카드 렌더(§1)는 그래프 **밖**에서(서비스가) 끝내 state에 실어 보낸다.

## ±N 윈도우 길이 근거 — "정당한 길이"

본 설계의 답은 **"고정 20줄"이 아니라 "트레이스 우선 + ±20행 패딩"** 이다.

### 추출 알고리즘 (`LogWindowRepositoryImpl`)

1. **트레이스 우선 조회.** `tripCorrelationIds` 각각에 대해 `log_event`에서 **같은 correlationId의 모든 행을 `time` 순으로** 가져온다(이상 요청의 완결된 인과 사슬). correlationId가 없으면(백그라운드 에러) 최근 `level>=40` 행 1개를 앵커로.
2. **트립 앵커 결정.** 트레이스 안 **첫 `level >= 40`(warning·error·fatal) 행**, 없으면 트레이스 첫 행.
3. **±N행 패딩.** 앵커 시각 기준 `log_event` 전체에서 `time` 순 **앞 20행 / 뒤 20행**을 덧댄다(correlationId 경계를 넘어 동시간대 맥락 확보 — LogAnomaly 세션 윈도우).
4. **상한 컷.** 합산·dedup 후 `maxLines`(기본 80)로 앵커 주변을 남긴다(14B 컨텍스트 폭주 방지).
5. **빈도 요약 동봉.** 범위 집계로 "최근 1h `action`/`level`별 횟수"(continuous aggregate 있으면 그쪽).

### 왜 기본값 20인가

- 한 grasp 요청 트레이스는 경험적으로 **5~15줄**. ±20이면 트레이스 + 앞뒤 여유 맥락을 덮는다.
- DeepLog 슬라이딩 윈도우 *m*≈10의 **안전계수 2배(=20)**. 경계에서 인과가 잘리는 위험을 줄인다.
- 총 ~40줄(상한 80)의 구조화 로그는 **수천 토큰** → 14B 로컬 컨텍스트에 안전.

> ±N **자동 튜닝**은 Out of scope(빌더 문서 line 354와 동일). 질의는 인덱스(`idx_log_action_time` 등 `(컬럼, time)` + `(time, logId)` PK)로 범위 스캔.

### 8.3 `src/shared/llm/llm-json.ts` — JSON 추출 헬퍼 (신규, prejudge에서 추출)

`prejudge.ts`의 `contentToString`/`extractJson`을 중립 위치로 옮긴다(선판단·분석 노드가 공유). 내용은 동일.

```ts
// AIMessage.content는 string | 복합블록[] 둘 다 가능 → 안전하게 문자열로.
export function contentToString(content: unknown): string {
  if (typeof content === "string") {
    return content;
  }
  if (Array.isArray(content)) {
    return content
      .map((part) =>
        typeof part === "object" && part !== null && "text" in part
          ? String((part as { text: unknown }).text)
          : "",
      )
      .join("");
  }
  return "";
}

// 마지막 ```json 블록(없으면 첫 { ~ 마지막 })만 뽑아 unknown으로 반환.
export function extractJson(text: string): unknown {
  const fenced = text.match(/```json\s*([\s\S]*?)```/i);
  const raw = fenced
    ? fenced[1]
    : text.slice(text.indexOf("{"), text.lastIndexOf("}") + 1);
  return JSON.parse(raw);
}
```

`EventStoreReaderRepositoryImpl`·`InsightCatalogRepositoryImpl` 패턴(생성자에 `PinoLogger` + `@Inject(DRIZZLE)`) 그대로.

```ts
import { Inject, Injectable } from "@nestjs/common";
import { and, asc, desc, gt, gte, inArray, lte, sql } from "drizzle-orm";
import { PinoLogger } from "nestjs-pino";
import type {
  AnomalyLogWindow,
  FrequencyRollupRow,
  LogWindowRow,
} from "@/llm-context/llm-context.type";
import { WINDOW_CONFIG } from "@/llm-context/repository/log-window.config";
import type { LogWindowRepository } from "@/llm-context/repository/log-window.repository";
import { DRIZZLE, type Drizzle } from "@/shared/database/drizzle.provider";
import { logEvents } from "@/shared/database/schema";
import { LogAction, LogContext } from "@/shared/logger/logging-context";

// log_event 한 행의 select 결과 형태(필요 컬럼만).
interface RawRow {
  time: Date;
  logId: string;
  level: number;
  action: string | null;
  correlationId: string | null;
  msg: string | null;
}

const ROW_COLUMNS = {
  time: logEvents.time,
  logId: logEvents.logId,
  level: logEvents.level,
  action: logEvents.action,
  correlationId: logEvents.correlationId,
  msg: logEvents.msg,
} as const;

@Injectable()
export class LogWindowRepositoryImpl implements LogWindowRepository {
  constructor(
    private readonly logger: PinoLogger,
    @Inject(DRIZZLE) private readonly db: Drizzle,
  ) {
    this.logger.setContext(LogWindowRepositoryImpl.name);
  }

  async buildWindow(tripCorrelationIds: string[]): Promise<AnomalyLogWindow> {
    try {
      const trace: RawRow[] = await this.fetchTrace(tripCorrelationIds);
      const anchor: RawRow | null = await this.resolveAnchor(trace);

      if (anchor === null) {
        return { rows: [], frequency: [], windowHours: WINDOW_CONFIG.frequencyHours };
      }

      const before: RawRow[] = await this.db
        .select(ROW_COLUMNS)
        .from(logEvents)
        .where(lte(logEvents.time, anchor.time))
        .orderBy(desc(logEvents.time))
        .limit(WINDOW_CONFIG.beforeCount);

      const after: RawRow[] = await this.db
        .select(ROW_COLUMNS)
        .from(logEvents)
        .where(gt(logEvents.time, anchor.time))
        .orderBy(asc(logEvents.time))
        .limit(WINDOW_CONFIG.afterCount);

      const rows: LogWindowRow[] = this.merge(
        [...trace, ...before, ...after],
        anchor,
      );
      const frequency: FrequencyRollupRow[] = await this.fetchFrequency(anchor.time);

      this.logger.debug(
        { [LogContext.COUNT]: rows.length },
        "이상 로그 윈도우 조립",
      );
      return { rows, frequency, windowHours: WINDOW_CONFIG.frequencyHours };
    } catch (err) {
      this.logger.error(
        { action: LogAction.DB_ERROR, err },
        "윈도우 조립 실패",
      );
      throw err;
    }
  }

  private async fetchTrace(ids: string[]): Promise<RawRow[]> {
    if (ids.length === 0) {
      return [];
    }
    return this.db
      .select(ROW_COLUMNS)
      .from(logEvents)
      .where(inArray(logEvents.correlationId, ids))
      .orderBy(asc(logEvents.time));
  }

  // 트레이스 안 첫 에러행 → 없으면 트레이스 첫 행 → 트레이스가 비면 최근 에러행.
  private async resolveAnchor(trace: RawRow[]): Promise<RawRow | null> {
    const firstError = trace.find((r) => r.level >= WINDOW_CONFIG.errorLevel);
    if (firstError !== undefined) {
      return firstError;
    }
    if (trace.length > 0) {
      return trace[0];
    }
    const latestError = await this.db
      .select(ROW_COLUMNS)
      .from(logEvents)
      .where(gte(logEvents.level, WINDOW_CONFIG.errorLevel))
      .orderBy(desc(logEvents.time))
      .limit(1);
    return latestError[0] ?? null;
  }

  // logId로 dedup → time 순 정렬 → 앵커 표시 → 앵커 주변 maxLines로 컷.
  private merge(raw: RawRow[], anchor: RawRow): LogWindowRow[] {
    const byId = new Map<string, RawRow>();
    for (const row of raw) {
      byId.set(row.logId, row);
    }
    const sorted = [...byId.values()].sort(
      (a, b) => a.time.getTime() - b.time.getTime(),
    );

    const anchorIndex = sorted.findIndex((r) => r.logId === anchor.logId);
    const capped = this.capAroundAnchor(sorted, anchorIndex);

    return capped.map((r) => ({
      time: r.time,
      level: r.level,
      action: r.action,
      correlationId: r.correlationId,
      msg: r.msg,
      isAnchor: r.logId === anchor.logId,
    }));
  }

  private capAroundAnchor(rows: RawRow[], anchorIndex: number): RawRow[] {
    if (rows.length <= WINDOW_CONFIG.maxLines) {
      return rows;
    }
    const half = Math.floor(WINDOW_CONFIG.maxLines / 2);
    const start = Math.max(0, anchorIndex - half);
    return rows.slice(start, start + WINDOW_CONFIG.maxLines);
  }

  private async fetchFrequency(anchorTime: Date): Promise<FrequencyRollupRow[]> {
    const windowStart = new Date(
      anchorTime.getTime() - WINDOW_CONFIG.frequencyHours * 3600 * 1000,
    );
    const rows = await this.db
      .select({
        action: logEvents.action,
        level: logEvents.level,
        count: sql<number>`count(*)::int`,
      })
      .from(logEvents)
      .where(
        and(gte(logEvents.time, windowStart), lte(logEvents.time, anchorTime)),
      )
      .groupBy(logEvents.action, logEvents.level);

    return rows.map((r) => ({ action: r.action, level: r.level, count: r.count }));
  }
}
```

### 8.8 `src/analysis/render.ts` — 사실 마크다운 렌더 (신규, 순수 함수)

노드가 state(구조체)를 **사실 .md**로 바꿔 LLM에 넣는다. 노드는 순수 함수라 NestJS 렌더러를 주입할 수 없으므로 **순수 함수**로 둔다. 셀 이스케이프는 `InsightCardRenderer.cell` 규칙을 재사용.

```ts
import type {
  AnomalyLogWindow,
  LogWindowRow,
} from "@/llm-context/llm-context.type";
import type {
  AnalysisDecision,
  GeneratedOutputs,
  RootCauseAnalysis,
} from "@/analysis/type/output.type";

function cell(value: string): string {
  return value.replace(/\s+/g, " ").trim().replace(/\|/g, "\\|");
}

function time(value: Date): string {
  return value.toISOString().slice(11, 23); // HH:mm:ss.SSS
}

// §2 이상 로그 맥락 (파이프 표 + 빈도 1줄) — Sui et al.
export function renderAnomalyWindow(window: AnomalyLogWindow): string {
  const freq =
    window.frequency.length === 0
      ? "빈도 집계 없음"
      : window.frequency
          .map((f) => `\`${f.action ?? "-"}\`(level ${f.level}) ${f.count}회`)
          .join(", ");

  const header =
    "| time | level | action | correlation_id | msg |\n| --- | --- | --- | --- | --- |";

  const body = window.rows
    .map((r: LogWindowRow) => {
      const mark = r.isAnchor ? " ← 트립 앵커" : "";
      return `| ${time(r.time)} | ${r.level} | ${cell(r.action ?? "-")} | ${cell(r.correlationId ?? "-")} | ${cell(r.msg ?? "-")}${mark} |`;
    })
    .join("\n");

  return [
    "## 2. 이상 로그 맥락 (±N 윈도우)",
    `> 빈도: 최근 ${window.windowHours}h — ${freq}.`,
    "",
    header,
    body,
  ].join("\n");
}

export function renderRootCause(rootCause: RootCauseAnalysis): string {
  return [
    "## 근본원인 분석",
    `- 요약: ${rootCause.summary}`,
    `- 타임라인: ${rootCause.timeline}`,
    `- 실패한 요청 의도: ${rootCause.failedIntent}`,
    `- 의심되는 Read Model 부족: ${rootCause.suspectedReadModelGap}`,
  ].join("\n");
}

export function renderDecision(decision: AnalysisDecision): string {
  return [
    "## 의사결정",
    `- 선택: ${decision.selected.join(", ") || "(없음 = 조치 불필요)"}`,
    `- 근거: ${decision.reasoning}`,
  ].join("\n");
}

export function renderOutputs(outputs: GeneratedOutputs): string {
  return ["## 생성된 출력", "```json", JSON.stringify(outputs, null, 2), "```"].join("\n");
}
```

### 8.14 `src/analysis/analysis.graph.ts` — 노드 import 추가 + 파일명 수정

`annalysis.graph.ts` → `analysis.graph.ts`로 리네임하고, 상단에 노드 import만 추가하면 디스크 본문이 그대로 동작한다.

```ts
import { END, START, StateGraph } from "@langchain/langgraph";
import { AnalysisState } from "@/analysis/analysis.state";
import { aggregateNode } from "@/analysis/nodes/aggregate.node";
import { decisionNode } from "@/analysis/nodes/decision.node";
import { newReadModelNode } from "@/analysis/nodes/new-read-model.node";
import { recommendationDocsNode } from "@/analysis/nodes/recommendation-docs.node";
import { rootCauseNode } from "@/analysis/nodes/root-cause.node";
import { versionSwitchNode } from "@/analysis/nodes/version-switch.node";

const ROUTE: Record<
  "versionSwitch" | "recommendationDocs" | "newReadModel",
  string
> = {
  versionSwitch: "genVersionSwitch",
  recommendationDocs: "genRecommendationDocs",
  newReadModel: "genNewReadModel",
};

export function buildAnalysisGraph() {
  const graph = new StateGraph(AnalysisState)
    .addNode("rootCause", rootCauseNode)
    .addNode("decision", decisionNode)
    .addNode("genVersionSwitch", versionSwitchNode)
    .addNode("genRecommendationDocs", recommendationDocsNode)
    .addNode("genNewReadModel", newReadModelNode)
    .addNode("aggregate", aggregateNode);

  graph.addEdge(START, "rootCause");
  graph.addEdge("rootCause", "decision");

  graph.addConditionalEdges(
    "decision",
    (state) => {
      const picked = state.decision?.selected ?? [];
      if (picked.length === 0) {
        return "aggregate";
      }
      return picked.map((kind) => ROUTE[kind]); // string[] = 병렬 분기
    },
    ["genVersionSwitch", "genRecommendationDocs", "genNewReadModel", "aggregate"],
  );

  graph.addEdge("genVersionSwitch", "aggregate");
  graph.addEdge("genRecommendationDocs", "aggregate");
  graph.addEdge("genNewReadModel", "aggregate");
  graph.addEdge("aggregate", END);

  return graph.compile();
}
```

### 8.15 `src/llm-context/llm-context.service.ts` — `detectOnce()` TODO 구현 (수정)

`LOG_WINDOW`·`InsightService`를 주입하고, 컴파일된 그래프를 1회 만들어 보관. triggered면 윈도우→카드→그래프→리포트 저장.

```ts
import * as fs from "node:fs";
import { join } from "node:path";
import { Inject, Injectable, OnModuleDestroy, OnModuleInit } from "@nestjs/common";
import { PinoLogger } from "nestjs-pino";
import { buildAnalysisGraph } from "@/analysis/analysis.graph";
import { InsightService } from "@/insight/insight.service";
import { LogConsumer } from "@/llm-context/kafka/log-consumer";
import { LOG_CONSUMER_CONFIG } from "@/llm-context/kafka/log-consumer.config";
import { PrejudgeChecked } from "@/llm-context/llm-context.type";
import {
  LOG_WINDOW,
  type LogWindowRepository,
} from "@/llm-context/repository/log-window.repository";
import { prejudge } from "@/llm-context/screener/prejudge";
import { LogAction, LogContext } from "@/shared/logger/logging-context";

@Injectable()
export class LLMContextService implements OnModuleInit, OnModuleDestroy {
  private timer: NodeJS.Timeout | null = null;
  private stopped: boolean = false;
  private readonly graph = buildAnalysisGraph(); // 컴파일 1회

  constructor(
    private readonly logger: PinoLogger,
    private readonly consumer: LogConsumer,
    private readonly insight: InsightService,
    @Inject(LOG_WINDOW) private readonly logWindow: LogWindowRepository,
  ) {
    this.logger.setContext(LLMContextService.name);
  }

  // onModuleInit/onModuleDestroy/runLoop 는 기존 그대로 (생략)

  async detectOnce(): Promise<PrejudgeChecked | null> {
    const batch = this.consumer.drainOnce();
    if (batch.length === 0) {
      return null;
    }

    const checked: PrejudgeChecked = await prejudge(batch);
    this.logger.info(
      {
        action: checked.triggered
          ? LogAction.LLM_PREJUDGE_TRIGGERED
          : LogAction.LLM_PREJUDGE_SKIPPED,
        [LogContext.COUNT]: batch.length,
        [LogContext.REASON]: checked.reason,
      },
      checked.triggered ? "선판단: 비정상" : "선판단: 정상",
    );

    if (checked.triggered) {
      await this.analyze(checked);
    }
    return checked;
  }

  private async analyze(checked: PrejudgeChecked): Promise<void> {
    const window = await this.logWindow.buildWindow(checked.tripCorrelationIds);
    const insightCards = await this.insight.renderAllCards();

    const result = await this.graph.invoke({ window, insightCards });

    const path = await this.writeReport(result.report ?? "", checked);
    this.logger.info(
      { action: LogAction.LLM_ANALYSIS_AGGREGATE_DONE, [LogContext.REPORT_PATH]: path },
      "분석 리포트 생성",
    );
  }

  private async writeReport(report: string, checked: PrejudgeChecked): Promise<string> {
    const id = checked.tripCorrelationIds[0] ?? "background";
    const dir = join(process.cwd(), "src/analysis/output");
    const path = join(dir, `analysis-${id}.md`);
    await fs.promises.mkdir(dir, { recursive: true });
    await fs.promises.writeFile(path, report);
    return path;
  }
}
```

> `detectOnce`의 반환 타입을 명시(`Promise<PrejudgeChecked | null>`)해 `runLoop`의 `triggeredLLM` 판정 로직은 그대로 둔다. 그래프 `invoke`의 결과 `report`는 `aggregate` 노드가 채운다.

## 검증 (end-to-end)

1. **빌드/규칙**: `tsc --noEmit` 통과, `any`·약어 식별자 0건(`CLAUDE.md`).
2. **트리거 → 윈도우**: `db.error` 등 실패 로그 produce → 선판단 트리거 → `buildWindow`가 트립 앵커 ±20행 + 빈도 반환.
3. **멀티에이전트 e2e**: rootCause → decision(1~3) → 선택 생성자 **병렬** → aggregate가 `analysis-*.md` 1개 산출. `llm.analysis.aggregate.done` 로깅.
4. **분기 정확성**: decision 2개 선택 시 두 출력이 `outputs`에 **모두** 보존(reducer) + 0개면 "조치 불필요" 리포트.
5. **포맷 점검**: 생성 `.md`를 14B 모델/뷰어로 열어 표·섹션 안 깨짐(He et al.·Sui et al.).
