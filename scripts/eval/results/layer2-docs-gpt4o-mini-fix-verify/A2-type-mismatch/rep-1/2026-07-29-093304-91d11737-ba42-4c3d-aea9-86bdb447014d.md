### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 | reason=[ { "expected": "number", "code": "invalid_type", "path": [ "grip_succeed" ], "message": "Invalid input: expected number, received string" } ] · file=반려동물용품_CR01_강아지공룡알장난감_02002_01_20230923.json → 원천 파일의 필수 필드 누락/타입 위반이 발생하여 Read Model의 grip_succeed 필드가 적절히 처리되지 못하고 있다. - src/insert/dto/toy-data.dto.ts의 toyDataSchema에서 grip_succeed는 z.number().int().min(0).max(1)로 정의되어 있으나, 실제 입력 데이터에서 문자열로 제공되고 있다.
- src/projection/projector/grip-result.projector.ts의 map 메서드에서 payload.grip_succeed가 grip_succeed로 매핑되지만, 이 값이 유효하지 않아 매핑 실패로 이어진다.

### Decision Drivers
- 원천 데이터의 타입 검증 강화
- Read Model의 데이터 적재 정상화

### Considered Options
#### 원천 데이터 수정 요청
- 접근: 원천 데이터의 grip_succeed 필드에 대한 타입 검증을 강화하고, 원천 데이터 수정 요청을 통해 올바른 타입의 값을 보장해야 한다.
- 제안 필드: grip_succeed
- 트레이드오프: 원천 데이터 수정 요청이 필요하며, 이로 인해 데이터 적재 지연이 발생할 수 있다.
```typescript
grip_succeed: z.number().int().min(0).max(1).refine(val => typeof val === 'number', { message: "Invalid input: expected number, received string", }),
```

### Decision Outcome
원천 데이터 수정 요청 — 원천 데이터의 grip_succeed 필드의 타입을 올바르게 수정하여 Read Model의 데이터 적재를 정상화할 수 있다.

### Consequences
- (+) Read Model의 데이터 적재가 정상화된다.
- (+) 원천 데이터의 품질이 향상된다.
- (−) 데이터 적재 지연이 발생할 수 있다.

### Non-Goals
- Read Model의 구조 변경
- 기존 데이터의 강제 수정
