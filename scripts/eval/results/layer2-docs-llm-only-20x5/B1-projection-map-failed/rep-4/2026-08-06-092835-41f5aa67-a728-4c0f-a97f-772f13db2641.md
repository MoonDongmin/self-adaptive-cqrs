- read_grip_result 스키마의 object_name 컬럼은 payload.objects[0].class_name을 참조. 빈 배열 시 인덱스 0 접근 실패 또는 Zod/프로젝터 검증 실패.
- grip-result.projector.ts 의 map() 메서드에서 if (payload.objects.length === 0) 조건이 throw new Error(...) 로직. 이 미적 예외 처리가 CatchUpRunner 의 배치 트랜잭션 롤백으로 이어짐.
- event_store 에 01e9b521-8c96-41ea-878d-22349bb4c763 eventId 가 적재된 상태. 투영 실패(poison event) lane 에 해당하여 격리·무해화 정책 필요.

### Decision Drivers
- 배치 트랜잭션 안전성 (Rollback 차단 vs 재개)
- 데이터 정립성 보존 (Strict validation 유지 vs Dead-letter 허용)
- Operational Complexity (프로젝터 수정 vs Infrastructure/SQL 검증)
- Schema/API 안정성 (변무 vs 변경)

### Considered Options
#### Dead-letter 처리 (Projector 수정)
- 접근: GripResultProjector.map() 의 빈 objects 예외 catch 로직 변경. throw 대신 null 또는 sentinel 반환, CatchUpRunner 에서 skip 처리.
- 제안 필드: object_name, map()
- 트레이드오프: 배치 트랜잭션 안전성 ↑, strict validation ↓, operational complexity ↓
```typescript
if (payload.objects.length === 0) { this.logger.error({ action: LogAction.MAP_FAILED, [LogContext.EVENT_ID]: event.eventId }, "objects 비어 있음 ← dead-letter"); return null; }
```

- 접근: 기존 strict validation 유지. event_store SELECT 로 결함 eventId 식별. CatchUpRunner 가 해당 global_seq 건너뛰기(skip) 또는 별도 dead-letter 테이블 적재.
- 제안 필드: event_id, global_seq
- 트레이드오프: data integrity ↑, operational complexity ↑, rollback overhead ↑
