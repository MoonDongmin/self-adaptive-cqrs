## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 50, `projection.map.failed`) objects 비어 있음 ← 트립 앵커 → GripResultProjector의 map() 로직이 빈 objects 배열을 만나며 hard throw를 발생, 이는 Read Model 투영 파이프라인의 에러 처리 정책 부재로 배치 롤백 유발. [corr:a4ba4a43-6c14-4ac0-8539-7312a5640c3f]
- (level 50, `db.error`) 투영 트랜잭션 실패 → 단일 결함 이벤트의 throw로 인해 DrizzleTx 배치 트랜잭션이 롤백됨, 정상 매핑된 preceding events도 영구 유실 상태. [corr:a4ba4a43-6c14-4ac0-8539-7312a5640c3f]
- `read_grip_result` 스키마의 `object_name:varchar`은 `payload.objects[0].class_name`을 참조로 정의되어 있음 [corr:a4ba4a43-6c14-4ac0-8539-7312a5640c3f]. 빈 배열은 인덱스 0 접근 실패 또는 명시적 예외 발생.
- `GripResultProjector.map()` 소스에서 `if (payload.objects.length === 0)` 조건이 true일 시 `throw new Error(...)`를 호출 [corr:a4ba4a43-6c14-4ac0-8539-7312a5640c3f]. 이는 Zod 검증 통과된 payload가 의미적 결함(빈 배열)을 만나며, `checkIntegrity` 훅를 활용하지 않고 직접 예외로 비침.
- `ProjectionService.catchUpGripResult()` 호출 시 `CatchUpRunner.run()` 내부에서 `projector.map()` 예외 전파로 `tx.rollback()`이 발생 [corr:a4ba4a43-6c14-4ac0-8539-7312a5640c3f]. 커서 advancement(`projection.cursor.advanced`)가 미이뤄져 catch-up 재개 시 동일 결함 이벤트 반복.

### Decision Drivers
- 배치 일관성 유지 (Rollback vs Skip)
- 결함 데이터 원천 추적/고립 (Poison Event 식별 vs Silent Ignore)
- Read Model 스키마 변경 최소화 (기존 테이블 활용 vs 신규 테이블)
- 운영 오버헤드 관리 (Cursor jump vs Batch retry)

### Considered Options
#### deadLetterSkip
- 접근: `GripResultProjector.map()` 수정하여 빈 objects 시나리오를 `throw` 대신 `IntegrityViolation` 반환 또는 sentinel skip flag.
- 제안 필드: batch consistency preserved, but attempt_num gap remains; requires runner adaptation to handle skip.
- 트레이드오프: 배치 일관성 유지(Driver 1 충족)이나 결함 고립/원천 추적(Driver 2 실패)로 기각.
```typescript
if (payload.objects.length === 0) { this.logger.error({ action: LogAction.MAP_FAILED, [LogContext.EVENT_ID]: event.eventId }, "objects 비어 있음"); return null; }
```

#### poisonEventIsolation
- 접근: `CatchUpRunner` 또는 `ProjectionService` 레벨에서 try-catch 적용, 결함 event_id 식별 SQL 실행, cursor jump skip, 재실행.
- 제안 필드: operational complexity increases, but guarantees strict poison isolation without altering projector logic deeply.
- 트레이드오프: 운영 오버헤드 증가(Driver 4 소모)나 배치 일관성+결함 고립 동부족(Driver 1,2 충족)으로 채택.
```typescript
try { await runner.run(projector); } catch (error) { const poisonRows = await db.query(poisonIdentifySql); if (poisonRows.length > 0) { cursor.jumpToNextSafe(); return retryCatchUp(cursor); } throw error; }
```

### Decision Outcome
poisonEventIsolation

### Consequences
- (+) 배치 트랜잭션 롤백 방지
- (+) 정상 preceding events 투영 보장
- (+) 결함 이벤트 영구 격리 로그 남김
- (−) 커서 점프 로직 추가 구현 필요
- (−) 재실행 오버헤드 발생
- (−) dead-letter tracking 테이블 연마 필요

### Non-Goals
- Read Model 스키마 확장(신컬럼/신테이블)
- 원천 payload objects 배열 채우기
- Zod coerce/default값 치환
