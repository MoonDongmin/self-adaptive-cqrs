#### Existing Reinforcement (Query Layer Registration)
- 접근: Insight 카드 집계 로직 등록(기존 read_grip_result 조회 + GROUP BY aggregation)
- 제안 필드: failure_count, failure_rate, rank_order
- 트레이드오프: 재투영 비용 제로, 스키마 변경 무부담, 다만 Query 레이어 캐시/인덱싱 최적화 필요
```typescript
SELECT object_name, COUNT(CASE WHEN grip_succeed = 0 THEN 1 END) AS failure_count, COUNT(CASE WHEN grip_succeed = 0 THEN 1 END) * 1.0 / COUNT(*) AS failure_rate FROM read_grip_result GROUP BY object_name ORDER BY failure_count DESC;
```

#### New Read Model Separation (Aggregation Table)
- 접근: 신규 집계 테이블 생성(newReadModel)
- 제안 필드: object_name, failure_count, total_attempts, failure_rate
- 트레이드오프: 투영 재실행 비용 발생, 스키마 확장, 동기화 로직 추가 과부하 (기각 대안)

### Decision Outcome
Existing Reinforcement (Query Layer Registration) - 기존 테이블 원천 데이터 활용과 Query 레이어 등록으로 스키마 확산과 투영 재실패 리스크 제로.

### Consequences
- (+) No schema change
- (+) Zero projection re-execution cost
- (+) Immediate catalog sync
- (−) Query layer cache/indexing optimization required for high-frequency ranking requests

### Non-Goals
- Read Model structural modification
- New projector/table generation
- Value coercion/fallback logic
