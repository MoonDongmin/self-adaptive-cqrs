## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 30, `-`) request completed ← 트립 앵커 → 요청 실행 시점에서 downstream 투_projection 로직의 metadata 매핑 오류가 누적됨. [corr:50ec1dfe-1653-49d7-8869-de64aff453c6]
- (level 20, `insight.card.rendered`) insight 카드 렌더 → Insight 카드 렌더링 시 기존 Read Model 스키마 구조는 적재 가능하나, projection 파이프라인의 attempt/scene 추출 정책이 미스매칭을 유발.
- read_multimodal.image_2d_file_name 가 현재 null 로 둠 — 추후 매핑 (Insight 카드) 이나 실제 map() 할당 시 payload["2D_image_file_name"] 로 채움. [corr:-]
- src/projection/projector/multimodal.projector.ts map() 함수에서 attemptNum: event.attemptNum 고정 주입 시, image_2d_file_name 의 실제 attempt metadata(예: _01_) 와 event.attemptNum(예: 02) 가 다름. [corr:-]
- checkIntegrity() 로직이 expectedAttempt: row.attemptNum 으로 비교 시, parsed.attemptNum 과 row.attemptNum 불일치 시 IntegrityViolation 반환. 이 위반은 DB 저장이 아닌 projection 실패로 유도됨. [corr:-]
- read_multimodal.attempt_num 컬럼의 의미는 같은 장면 내 파지 시도 번호이나, 현재 projector 가 이벤트 메타데이터를 무조건 복사함. 파일명 regex MODAL_FILE_NAME_RE 는 정의되어 있으나 map() 에서 미사용됨. [corr:-]

### Decision Drivers
- Ground Truth Priority (파일명 metadata vs 이벤트 시도)
- Integrity Violation Handling (skip vs fix)
- Schema Stability (avoid new tables if possible)

### Considered Options
#### map() attemptNum override from file metadata
- 접근: MultiModalProjector.map() 수정. image_2d_file_name parsing 시 extracted attemptNum 을 row.attemptNum 에 매핑. video 는 scene 만 일치 확인.
- 제안 필드: map(), checkIntegrity()
- 트레이드오프: 재투영 비용 발생, 기존 attempt_num semantics 변경(이벤트 시도 vs 파일명 시도). 파일명 시도가 ground truth 이므로 권장.
```typescript
const parsed2d = parseModalFileName(payload["2D_image_file_name"]); return { sceneKey: event.streamId.replace(/^grip-attempt:/, ""), attemptNum: parsed2d ? parsed2d.attemptNum : event.attemptNum, occurredAt: event.occurredAt, image2dFileName: payload["2D_image_file_name"], image2dUri: null, videoFileName: payload.video_file_name, videoUri: null, streamId: event.streamId, globalSeq: event.globalSeq };
```

#### integrity violation skip & flag table
- 접근: read_multimodal 유지, 신규 read_multimodal_flag 테이블 추가. mismatch 시 skip 기존, insert 신규 flag.
- 제안 필드: src/shared/database/schema/service/read-multimodal-flag.ts, map(), upsert()
- 트레이드오프: 스키마 확만, 조회 API 복잡성 증가. 과kill.
```typescript
// 신규 flag 테이블 upsert 로직 구현 시 mismatch row.insert(readMultimodalFlag).values({ sceneKey: row.sceneKey, attemptNum: row.attemptNum, isMismatch: true });
```

### Decision Outcome
map() attemptNum override from file metadata

### Consequences
- (+) 정합성 검사 실패 근본원인 해결
- (+) DB 일관성 유지
- (+) downstream sensor/LLM 비교 정확도 향상
- (−) affected stream 재투영 latency 발생
- (−) 기존 attempt_num semantics 변경으로 grip_result projector 의존성 확인 필요

### Non-Goals

- schema 확만
- grip_result projector 로직 수정
