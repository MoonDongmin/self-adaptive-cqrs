## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → Zod number 타입 검증 거절로 camera_info.camera_intrinsic_param.cody 필드 null 유입이 원천 파일의 필수 필드 누락/타입 위반을 드러남 [corr:c3227901-01f4-4469-a0e2-e5d471ed0d96]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → Zod number 타입 검증 거절로 camera_info.camera_intrinsic_param.fx 필드 null 유입이 원천 파일의 필수 필드 누락/타입 위반을 드러남 [corr:c3227901-01f4-4469-a0e2-e5d471ed0d96]
- `insert.file.failed` 로그 [corr:c3227901-01f4-4469-a0e2-e5d471ed0d96]는 적재 단계 Zod 검증 실패로, 결함 파일이 event_store 미append 되므로 Read Model 구조(`read_grip_result`, `read_multimodal`)는 정상 유지된다.
- Insight 카드 `GripAttemptRecorded`의 `camera_info.camera_intrinsic_param:object` 의미는 카메라 내부 파라미터(fx,fy,cx,cy, k1..k6, codx,cody)가 Read Model의 재료로, 현재 DTO(`src/insert/dto/toy-data.dto.ts`)에서 `cody: z.number()`와 `fx: z.number()` 정의가 `.nullable()` 미적용해 strict number 타입 강제한다.
- Projector(`GripResultProjector`, `MultiModalProjector`)의 `map` 메서드는 `toyDataSchema.parse(event.payload)` 호출 시 Zod 거절이 throw error, 투영이 중단되어 Read Model 컬럼(`sceneKey`, `attemptNum`, `objectName`, `gripSucceed` 등)에 결함 값 유입되지.
- 격 isolation policy 적용해 나머지 25개 파일(ok)은 정상 append & projection 진행, 후속 `projection.request/start/mapped` [corr:c3227901-01f4-4469-a0e2-e5d471ed0d96]는 정상 궤도.

### Decision Drivers
- Data Integrity Preservation (원천 결함 숨김 금지)
- System Reliability & Isolation Policy (배치 격리 유지)
- Operational Overhead vs Correctness (DB/Code 변경 최소화)
- Source Data Governance (외부 수정 요청 수용)

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청
- 접근: Zod strict validation 유지, 실패 파일 목록 모니터링/알림 보강
- 제안 필드: monitoring/alert 로직
- 트레이드오프: 재투영 비용 0, 리스크 0, 보장된 데이터 무해화
```typescript
if (insert.failedFiles.length > 0) { logger.warn({ action: LogAction.FILE_REJECTED }, "Zod 검증 거절 파일 발생 → 원천 데이터 수정 요청"); }
```

#### 무유입 검증 절차
- 접근: batch.done 후 event_store SELECT로 미유입 확인
- 제안 필드: event_store verification query
- 트레이드오프: DB overhead 발생, 정합성 확증
```typescript
const count = await db.select().from(eventStore).where(eq(streamId, 'grip-attempt:..._02024')).and(eq(attemptNum, 1)).count();
```

#### Zod schema 완화 (기각 대안)
- 접근: `z.number().nullable()` 적용
- 제안 필드: toyDataSchema 수정
- 트레이드오프: Data Integrity Driver 졌음, 원천 결함 숨김, downstream projection semantic drift 리스크

### Decision Outcome
거절 유지 + 원천 데이터 수정 요청

### Consequences
- (+) Zod strict validation 유지로 원천 결함이 Read Model 유입 차단 보장.
- (+) 배치 격리(isolation policy) 기존 궤도 그대로 유지, 후속 projection 정상 진행.
- (+) DB/Read Model 스키마 변경 없음으로 API 호환성 및 catch-up 커서 점프 무해.
- (−) 실패 파일 발생 시 외부 원천 데이터 수정 요청 프로세스 추가 운영 부담.
- (−) 모니터링/alert 보강 로직 추가 개발 시간 소모.

### Non-Goals
- Zod schema 완화(optional/nullable) 또는 z.coerce·default 값 치환.
- 결함 추적용 신규 테이블 생성.
- Read Model 컬럼 구조 변경.
