### Decision Drivers
- 원천 데이터 무해화 원칙(거절 유지)
- 적재 단계 Zod 검증 신뢰도
- Read Model 구조 안정성 보장
- 추적/검증 가시성 최소화

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청 (권장)
- 접근: InsertService 의 Zod 검증 로직(toyDataSchema) 을 그대로 유지. 실패 파일 목록을 외부 보고/알림 보강으로 전환하여 원천 데이터 팀에 수정 요청.
- 제안 필드: alertingChannel, sourceFileList
- 트레이드오프: 재투영 비용 0, Read Model 안정성 보장, 단 대외 보고 절차 추가 필요.
```typescript
// src/insert/dto/toy-data.dto.ts 유지 그대로. 실패 파일 추적은 InsertService.batchProcess 로직에 failedFiles.push(file) 만 추가.
```

#### 무유입 검증 절차
- 접근: ProjectionService 또는 별도 검증 스크립트에서 event_store 조회를 실행으로 거절된 stream/attempt 의 미유입을 공식화.
- 제안 필드: verificationQuery, expectedCount
- 트레이드오프: DB 조회 오버헤드 발생, Read Model 정립 과정 무변, 격리 확신 확보.

### Decision Outcome
거절 유지 + 원천 데이터 수정 요청 (권장)

### Consequences
- (+) 원천 payload 의 무해화 원칙 준수(거절 유지).
- (+) event_store 에 결함 이벤트 유입 차단으로 Read Model(read_grip_result, read_multimodal) 정립 과정 무변.
- (+) 재투영 오버헤드 0, projection.cursor 추적 일관성 유지.
- (−) 대외 보고/알림 절차 추가 필요로 원천 데이터 수정 요청 지연 발생.
- (−) 일시 scene_key coverage gap 발생 until 파일 보강.

### Non-Goals
- Zod 스키마(toyDataSchema) 의 필수 object 타입 완화(optional 화).
- z.coerce·기본값 치환으로 적재 통과 유도.
- 결함 추적용 신규 테이블 또는 Read Model 컬럼 추가.
