- Insight card GripAttemptRecorded mandates grip_data and robot_tf as required objects. The DTO schema in src/insert/dto/toy-data.dto.ts enforces this strictly via z.object({ grip_data: ..., robot_tf: ... }).
- Projector implementations (src/projection/projector/grip-result.projector.ts, multimodal.projector.ts) invoke toyDataSchema.parse(event.payload). Since the failed events are not appended to event_store, projectors never encounter them; the Read Model structure is intact.
- Failed file names ..._02004_01_20230923.json and ..._02005_01_20230923.json indicate scene keys 반려동물용품_CR01_강아지공룡알장난감_02004 and ..._02005 with attempt number 1.

### Decision Drivers
- Data Integrity Preservation (Zod gatekeeper intent)
- System Consistency Guarantee (Zero-insertion verification)
- Operational Overhead vs Reliability (Minimal code change preferred)
- External Fix Coordination (Source correction as primary remedy)

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청 (권장)
- 접근: Maintain strict Zod rejection in src/insert/dto/toy-data.dto.ts. Add alert/logging in InsertService to flag missing payloads and coordinate external file correction.
- 제안 필드: LogAction, InsertResult
- 트레이드오프: Zero projection code change, preserves data integrity, requires external fix coordination.
```typescript
async insertToyData(): Promise<InsertResult> { const result = await this.insertBatch(); if (result.failedFiles.length > 0) { this.logger.warn({ action: LogAction.FILE_REJECTED }, `적재 거절 발생: ${result.failedFiles.join(", ")}`); } return result; }
```

#### 무유입 검증 절차
- 접근: After batch completion, query event_store for zero-count verification of failed streams/attempts to guarantee system consistency.
- 제안 필드: EventStoreReaderRepository
- 트레이드오프: Adds DB round-trip overhead, no load logic alteration.
```typescript
async verifyZeroInsertion(sceneKey: string, attemptNum: number): Promise<boolean> { const count = await this.eventStoreReader.countWhere({ streamId: `grip-attempt:${sceneKey}`, attemptNum }); return count === 0; }
```

#### Zod schema 완화 (기각 대안)
- 접근: Relax required fields to optional or coerce undefined.
- 제안 필드: toyDataSchema
- 트레이드오프: Fails Decision Driver Data Integrity Preservation and violates Defect Value Neutralization Principle by masking source defects.

### Decision Outcome
거절 유지 + 원천 데이터 수정 요청 (권장)

### Consequences
- (+) Maintains strict Zod boundary
- (+) Prevents phantom data in Read Model
- (+) Clear failure signal for upstream coordination
- (−) Requires manual source file correction
- (−) Temporary gap in scene coverage until fix arrives

### Non-Goals
- Modifying Zod schema to accept undefined
- Injecting fallback values
- Creating new tracking tables
