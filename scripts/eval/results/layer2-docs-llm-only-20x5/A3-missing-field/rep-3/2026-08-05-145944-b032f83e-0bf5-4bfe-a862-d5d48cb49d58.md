### Decision Drivers
- 결함 값 무해화 원칙(거절 유지 + 원천 수정 요청) 준수
- Event Store 무유입 검증 절차 신뢰도 확보
- API/Read Model 스키마 변경 최소화 (Backward Compatibility)
- Operational Overhead vs Remediation Workflow Tradeoff

### Considered Options
#### 무유입 검증 및 원천 데이터 수정 요청
- 접근: 배치 완료 후 event_store 조회를 실패 stream/attempt 에 대해 0 확인, 외부 시스템 알림 보강.
- 제안 필드: containmentSql, apiVersionImpact
- 트레이드오프: Operational overhead 증가(추가 SELECT), but guarantees store integrity and aligns with Driver 1 & 3.

- 제안 필드: -
- 트레이드오프: Violates Driver 1 (defect value sanitization principle), introduces null/undefined into Read Model, breaks consistency rules and integrity checks in multimodal.projector.ts checkIntegrity().

### Decision Outcome
무유입 검증 및 원천 데이터 수정 요청

### Consequences
- (+) Event Store integrity maintained
- (+) Read Model schema untouched
- (+) upstream data quality issue clearly surfaced for remediation
- (−) Requires external monitoring/verification step post-batch

### Non-Goals

- coercion/default injection
- new Read Model creation
- modifying Zod guard behavior
