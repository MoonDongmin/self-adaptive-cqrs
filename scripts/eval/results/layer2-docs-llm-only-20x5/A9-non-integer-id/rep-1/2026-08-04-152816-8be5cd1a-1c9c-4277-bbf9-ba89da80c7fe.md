### Decision Drivers
- Zod 검증은 시스템 의도된 방어 동작이므로 `.int()` 스키마 완화를 금지한다.
- 실패 이벤트는 `event_store` 미유입 상태이므로 Read Model 구조 수정이 불필러하다.
- 원천 데이터 타입 위반(id, num_keypoints float 유입)이 근본 원인이다.
- 격리 권고는 무유입 검증 SQL로 미적재 확인을 수행해야 한다.

### Considered Options
#### 원천 데이터 정화 요청
- 접근: 유지 현 Zod `.int()` 검증, 실패 로그 방출로 원천 사일로 수정 요청.
- 제안 필드: src/insert/dto/toy-data.dto.ts, src/projection/projector/grip-result.projector.ts
- 트레이드오프: 코드 변경 0, 리스크 없음. 다만 원천 데이터 품질 관리가 외부로 위양됨.


- 접근: 적재 실패 시 `event_store` 조회를 통해 미적재 확인을 수행.

### Decision Outcome
원천 데이터 정화 요청

### Consequences
