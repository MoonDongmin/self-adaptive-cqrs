## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → Zod 검증 단계에서 grip_succeed 필드의 타입/값 불일치로 인해 이벤트 적재가 차단되며, read_grip_result Read Model에 해당 시도의 파지 성공 여부가 누락됨을 드러냄. [corr:eaecb9be-2a75-4755-a57f-d869a35a5594]
- toy-data.dto.ts의 grip_succeed 스키마는 z.number().int().min(0).max(1)으로 엄격히 정의되어 있으나, 실제 적재 데이터는 문자열 또는 범위를 벗어난 값을 포함하고 있어 insert.file.failed를 유발함 [corr:eaecb9be-2a75-4755-a57f-d869a35a5594].
- GripResultProjector.map() 함수는 검증 실패 시 즉시 예외를 던지며, 이로 인해 read_grip_result 테이블의 grip_succeed 컬럼에 해당 시도의 값이 투영되지 못함.
- read_multimodal의 image_2d_uri와 video_uri는 현재 MultiModalProjector.map()에서 명시적으로 null로 할당되어 있으며, 이는 미디어 URI 매핑 로직이 아직 구현되지 않았음을 의미함.
- GripResultProjector는 checkIntegrity 인터페이스를 구현하지 않아, 구조 검증 통과 후 의미적 오류를 Read Model 단계에서 추가 검증하지 않음.

- (+) Toy-Data 배치 적재의 연속성 보장.
- (−) 원본 값 정정 시 정확성 손실 가능성 존재 (문자열/범위 오류 데이터가 강제로 0 또는 1로 변환됨).
- (−) 정정된 값의 원본 추적 불가 (원본 로그만 보존).

### Non-Goals
- read_multimodal의 image_2d_uri 및 video_uri 매핑 로직 구현.
- grip_succeed 외 필드 (예: camera_info, objects)의 검증 강화.
