### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → grip_succeed 필드의 문자열 입력이 Zod 검증에서 차단되어 배치 적재가 중단되고, read_grip_result 및 read_multimodal의 정상 투영이 차단됨. [corr:ab071bbf-7a02-4b36-a6cf-76cfe5a3191a]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → Zod 검증 실패로 인해 배치 파이프라인이 종료되며, Read Model으로의 데이터 흐름이 영구 차단됨. [corr:ab071bbf-7a02-4b36-a6cf-76cfe5a3191a]
- toy-data.dto.ts의 grip_succeed: z.number().int().min(0).max(1)은 숫자 타입을 엄격히 요구하며, 문자열 입력 시 즉시 예외를 발생시킴.
- GripResultProjector.map()은 toyDataSchema.parse(event.payload) 호출 시 검증 실패를 던져 read_grip_result의 grip_succeed: smallint 컬럼에 데이터가 적재되지 못하게 함.
- MultiModalProjector도 동일 DTO를 참조하므로 image_2d_uri, video_uri가 null로 초기화되는 현상과 함께 전체 투영 파이프라인이 차단됨.
- 로그 테이블에 stream_id 컬럼이 존재하지 않아, 격리 확인 SQL에서는 correlation_id를 식별자로 활용하여 미유입 상태를 검증함.

### Considered Options
#### DTO 검증 단계에 .coerce() 적용 (기존 보강)

- 트레이드오프: 데이터 품질 감춤 리스크 있으나, 기존 Read Model 변경 없이 배치 연속성을 확보. 재투영 비용 없음.

- 제안 필드: projection_cursor.last_event_seq, event_store.global_seq
- 트레이드오프: 인프라 수정 필요. 엄격한 검증 유지하나, 실패 이벤트의 데이터 손실 발생 가능.

- (+) 단일 이벤트의 타입 불일치로 인한 배치 중단 현상 즉시 해소.
- (+) 기존 read_grip_result 스키마와 API 엔드포인트 변경 없이 하위 호환성 유지.
- (+) Zod 검증 파이프라인을 거치지 않고 Read Model에 도달하는 poison event 유입 차단.
- (−) 문자열 입력이 숫자로 자동 변환되며, 원천 데이터의 타입 오류가 숨겨질 수 있음.
- (−) 향후 grip_succeed 필드 검증 로직이 .coerce()에 의존하게 되어, 엄격한 타입 검사가 필요한 도메인 확장에서 추가 작업 필요.

### Non-Goals
- 신규 Read Model 생성 또는 기존 테이블 컬럼 타입 변경
- API 엔드포인트 경로 또는 응답 스키마 수정
- Zod 검증 로직 완전 제거 또는 느슨한 허용 규칙 적용
