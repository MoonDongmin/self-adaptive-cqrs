## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → Zod 검증(grip_succeed 타입/범위) 실패로 이벤트 저장이 차단되어 read_grip_result 및 read_multimodal 투영이 중단됨. [corr:df533c89-4a61-4bf4-abd0-b8cbbf3e06e7]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → 동일 배치 내 후속 파일도 동일한 스키마 불일치로 적재 실패하며 Read Model 갱신이 누락됨. [corr:df533c89-4a61-4bf4-abd0-b8cbbf3e06e7]
- src/insert/dto/toy-data.dto.ts의 검증 스키마는 grip_succeed: z.number().int().min(0).max(1)으로 엄격히 정의되어 있으나, 실제 Toy-data는 문자열과 1 초과 값을 전달함 [corr:df533c89-4a61-4bf4-abd0-b8cbbf3e06e7].
- GripResultProjector.map()은 검증 스키마 파싱 호출 시 예외를 던지며 투영을 중단하므로, read_grip_result의 gripSucceed: smallint 컬럼에 오염 데이터가 유입되지 않았으나 정상 데이터도 투영되지 않음.
- read_multimodal의 image2dUri, videoUri는 현재 프로젝트에서 null로 고정되어 있어 본 건과 무관하나, 동일 배치의 적재 실패로 인해 image2dFileName 등 파일명 매핑도 누락됨.

### Decision Drivers
- 데이터 정합성 유지 (오염 값의 Read Model 유입 차단)
- 적재 파이프라인 연속성 (실패 이벤트의 격리 및 정상 데이터 재투영 보장)
- 운영 복잡도 (격리 SQL, 커서 관리, 수동 재투영 절차의 명확성)
- API 안정성 (기존 조회 엔드포인트 및 스키마 변경 최소화)

### Considered Options
#### optionA
- 접근: toy-data.dto.ts의 grip_succeed 필드에 .pipe(z.coerce.number().int()) 및 .refine() 추가
- 제안 필드: toyDataSchema.grip_succeed
- 트레이드오프: 적재 성공률 상승 but 데이터 품질 은폐 및 재투영 필요성 발생
```typescript
grip_succeed: z.coerce.number().int().min(0).max(1).refine((v) => v === 0 || v === 1, { message: "grip_succeed must be 0 or 1" }),
```

#### optionB
- 접근: 검증 실패 이벤트를 event_store에 격리 저장하고, GripResultProjector에 정합성 검사 로직을 추가하여 오염 행을 차단
- 제안 필드: toyDataSchema, GripResultProjector.checkIntegrity
- 트레이드오프: 데이터 품질 보장 but 운영 절차(격리 SQL + 수동 재투영) 필요
```typescript
checkIntegrity(row, event): IntegrityViolation[] { if (row.gripSucceed !== 0 && row.gripSucceed !== 1) { return [{ readModelName: "read_grip_result", sceneKey: row.sceneKey, attemptNum: row.attemptNum, streamId: row.streamId, globalSeq: row.globalSeq, ruleName: "gripSucceedRange", affectedColumns: ["grip_succeed"], observedValue: String(row.gripSucceed), expected: "0 or 1", detail: `grip_succeed=${row.gripSucceed}는 허용 범위(0~1)를 벗어남.` }]; } return []; },
```

### Decision Outcome
optionB

### Consequences
- (+) 오염된 grip_succeed 값이 Read Model에 유입되지 않아 조회 정확도 유지
- (+) Poison Event 격리로 인해 정상 이벤트의 재투영이 가능해져 파이프라인 연속성 확보
- (+) 정합성 검사 로직 추가 시 향후 유사 스키마 불일치를 조기에 탐지 가능
- (−) 격리된 이벤트에 대한 수동 재투영 절차 필요로 운영 부담 증가
- (−) 검증 실패 시 즉시 적재가 차단되어 배치 완료 시간 지연 발생 가능
