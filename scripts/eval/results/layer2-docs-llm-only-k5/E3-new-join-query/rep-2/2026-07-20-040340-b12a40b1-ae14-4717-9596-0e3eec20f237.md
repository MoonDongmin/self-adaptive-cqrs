### Considered Options
#### DB View 생성
- 접근: read_grip_result와 read_multimodal을 scene_key와 attempt_num으로 조인하는 읽기 전용 뷰를 생성. 기존 프로젝터 수정 불필요.
- 제안 필드: grip_succeed, object_name, image_2d_file_name, video_file_name
- 트레이드오프: 구현 비용 최소, 읽기 성능 우수. 하지만 image_2d_uri와 video_uri가 null인 상태는 유지되며, 향후 URI 매핑 로직이 추가되면 뷰 정의도 수정 필요.
```typescript
CREATE VIEW insight_card_view AS SELECT g.scene_key, g.attempt_num, g.grip_succeed, g.object_name, m.image_2d_file_name, m.video_file_name, m.image_2d_uri, m.video_uri FROM read_grip_result g JOIN read_multimodal m ON g.scene_key = m.scene_key AND g.attempt_num = m.attempt_num;
```

#### 신규 InsightCardProjector 도입
- 접근: insight-card-projector를 새로 구현하여 두 테이블의 필드를 단일 행으로 합쳐서 read_insight_card에 투영.
- 제안 필드: scene_key, attempt_num, grip_succeed, object_name, image_2d_file_name, video_file_name, image_2d_uri, video_uri
- 트레이드오프: 읽기 성능 최적화, 단일 테이블 조회로 UI 로직 단순화. 하지만 투영 비용 증가, 데이터 중복 저장, 기존 두 프로젝터의 실패 시 정합성 유지 필요.

return { sceneKey: event.streamId.replace(/^grip-attempt:/, ""), attemptNum: event.attemptNum, gripSucceed: payload.grip_succeed, objectName: payload.objects[0].class_name, image2dFileName: payload["2D_image_file_name"], videoFileName: payload.video_file_name, image2dUri: null, videoUri: null, streamId: event.streamId, globalSeq: event.globalSeq };
