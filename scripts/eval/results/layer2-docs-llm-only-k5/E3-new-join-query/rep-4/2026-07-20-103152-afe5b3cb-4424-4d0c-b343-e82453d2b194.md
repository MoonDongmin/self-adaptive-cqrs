- 도메인 정합성: 분리된 모델 유지 vs 통합 모델 도입

- 재투영 비용 및 유지보수 부담

### Considered Options
#### 신규 통합 Read Model 생성
- 접근: src/shared/database/schema/service/read-insight-card.ts에 테이블 정의, src/projection/projector/insight-card.projector.ts에 통합 매핑 로직 구현. GripAttemptRecorded 이벤트 수신 시 양쪽 필드를 조인하여 단일 행으로 적재.
- 제안 필드: scene_key, attempt_num, object_name, grip_succeed, gripper_type, occurred_at, grip_2d_pose, grip_3d_pose, robot_tf, human_annotation_grasp, image_2d_file_name, image_2d_uri, video_file_name, video_uri, stream_id, global_seq
- 트레이드오프: 재투영 비용 발생 및 저장소 증가. 하지만 도메인 경계 명확화, URI 매핑 로직 중앙화, 향후 3D/메타데이터 확장 용이.

#### 기존 테이블 조인 뷰 활용
- 접근: PostgreSQL에 read_grip_result와 read_multimodal을 조인하는 뷰 생성. 컨트롤러에서 해당 뷰를 조회하도록 변경.
- 제안 필드: 기존 두 테이블 컬럼 전체 조인
- 트레이드오프: 신규 DB 객체 생성 비용 최소화. 하지만 image_2d_uri/video_uri가 여전히 null이므로 UI 렌더링 실패 가능성 높음. 조인 성능은 인덱스 의존적.
```typescript
CREATE VIEW v_insight_card AS SELECT r.scene_key, r.attempt_num, r.object_name, r.grip_succeed, r.gripper_type, r.occurred_at, r.grip_2d_pose, r.grip_3d_pose, r.robot_tf, r.human_annotation_grasp, m.image_2d_file_name, m.image_2d_uri, m.video_file_name, m.video_uri, r.stream_id, r.global_seq FROM read_grip_result r JOIN read_multimodal m ON r.scene_key = m.scene_key AND r.attempt_num = m.attempt_num;
```
