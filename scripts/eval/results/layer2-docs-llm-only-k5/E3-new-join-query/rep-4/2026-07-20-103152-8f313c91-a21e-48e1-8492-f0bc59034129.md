### Context (근거)

- (level 40, `insight.card.miss`) insight 카드 없음: 파지 결과와 해당 시도의 이미지·영상 경로를 한 화면에서 함께 보고 싶다. → 해당 로그는 read_grip_result와 read_multimodal이 분리되어 있어, 클라이언트가 요구하는 파지 결과+미디어 경로 동시 조회를 수행할 통합 Read Model(Insight 카드)이 부재함을 드러낸다. [corr:8f313c91-a21e-48e1-8492-f0bc59034129]
- 현재 read_grip_result와 read_multimodal은 동일한 키 scene_key, attempt_num를 공유하지만, 조회 계층에서 이를 조인하는 통합 Read Model이 정의되지 않았다. [corr:8f313c91-a21e-48e1-8492-f0bc59034129]
- MultiModalProjector.map() 메서드에서 image2dUri와 videoUri를 명시적으로 null로 할당하고 있어, 미디어 경로 매핑 로직이 아직 구현되지 않은 상태이다. (파일: src/projection/projector/multimodal.projector.ts)
- ProjectionController에는 /projection/grip-result와 /projection/multimodal 엔드포인트만 존재하며, 두 테이블을 결합한 Insight 카드 조회 API는 구현되지 않았다. (파일: src/projection/projection.controller.ts)
- 이벤트 페이로드는 GripAttemptRecorded를 통해 2D_image_file_name, video_file_name을 제공하지만, 현재 Read Model은 파일명만 저장하고 URI 변환 또는 조인 뷰를 제공하지 않는다.

### Decision Drivers
- 읽기 성능 및 조인 복잡도 관리
- 기존 Read Model 안정성 및 스키마 변경 리스크
- 투영 파이프라인 유지보수성

### Considered Options
#### 기존 read_multimodal에 조인용 컬럼 추가 (기존 보강)
- 접근: read_multimodal 테이블에 grip_succeed, object_name 등 조인 대상 컬럼을 추가하고, MultiModalProjector.map()에서 원천 이벤트 페이로드를 직접 파싱해 함께 적재.
- 제안 필드: grip_succeed, object_name
- 트레이드오프: 읽기 조인 비용 제거, 저장소 중복 증가. 리스크: 스키마 변경으로 기존 클라이언트 영향 가능성.
```typescript
return { sceneKey, attemptNum, occurredAt, image2dFileName: payload["2D_image_file_name"], image2dUri: null, videoFileName: payload.video_file_name, videoUri: null, streamId, globalSeq, gripSucceed: payload.grip_succeed, objectName: payload.objects[0].class_name };
```

#### 신규 통합 Read Model read_grip_insight 추가 (신규 분리)
- 접근: read_grip_insight 테이블 생성 및 전용 InsightProjector 구현. 두 프로젝터의 결과를 DB에서 조인하거나, 단일 프로젝트가 ES 이벤트를 파싱해 통합 행을 생성.
- 제안 필드: scene_key, attempt_num, grip_succeed, object_name, image_2d_uri, video_uri
- 트레이드오프: 읽기 성능 최적화, 투영 파이프라인 확장 필요. 리스크: 신규 테이블 관리 오버헤드.
