- 하위 파이프라인 연속성
- 검증 엄격도 유지 여부

### Considered Options
#### 검증 스키마 선택사항 전환 및 Projector 기본값 매핑 (기존 Read Model 보강)
- 접근: toyDataSchema에서 grip_data, robot_tf에 .optional() 적용. GripResultProjector.map()에서 누락 시 빈 객체 또는 null을 할당하여 read_grip_result에 부분 데이터로 적재.
- 제안 필드: grip_data, robot_tf
- 트레이드오프: 재투영 비용 없음, 리스크 낮음(부분 데이터 허용). 단, 하위 호환성 유지 필요.

const gripDataSchema = z.object({ ... }).optional(); const robotTfSchema = z.object({ ... }).optional(); return { ..., grip2dPose: payload.grip_data?.grip_2d_pose ?? null, grip3dPose: payload.grip_data?.grip_3d_pose ?? null, robotTf: payload.robot_tf ?? null, ... };

#### 검증 실패 이벤트 격리 커서 업데이트 (Poison Event 건너뛰기)
- 접근: CatchUpRunner 또는 프로젝트터 래퍼에서 검증 실패 시 예외 대신 경고 로그를 기록하고 해당 이벤트의 커서를 진행시켜 다음 이벤트를 처리하도록 변경.
- 제안 필드: projection_cursor 업데이트 로직, 예외 전파 방지 래퍼
- 트레이드오프: 배치 지연 해소. 단, 결함 데이터는 Read Model에 누락되므로 하위 단계에서 별도 처리 필요.

- v1 자산(테이블/엔드포인트/프로젝터 name) 무손상
- PK (scene_key, attempt_num) 유지
- TypeScript any 금지
- 식별자 전체 단어
- DDL 실행·API 컷오버는 인간 승인 후에만 (human-in-the-loop)
