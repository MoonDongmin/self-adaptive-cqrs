### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → Zod 검증 실패로 인해 read_grip_result의 grip2dPose, grip3dPose, robotTf 컬럼에 대한 투영이 차단됨. [corr:cdc74982-d747-4baf-87ec-987e5bed6501]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → Zod 검증 실패로 인해 read_grip_result의 grip2dPose, grip3dPose, robotTf 컬럼에 대한 투영이 차단됨. [corr:cdc74982-d747-4baf-87ec-987e5bed6501]
- src/insert/dto/toy-data.dto.ts의 toyDataSchema는 grip_data, robot_tf를 필수 객체로 정의.
- src/projection/projector/grip-result.projector.ts의 map() 메서드에서 toyDataSchema.parse(event.payload) 호출 시 실패하면 즉시 예외를 던져 배치 처리를 중단.
- read_grip_result 스키마에서 grip2dPose, grip3dPose, robotTf는 jsonb 타입으로 정의되어 null 허용이 가능하나, 현재 검증 로직이 이를 차단하여 해당 컬럼에 데이터가 적재되지 않음.
- MultiModalProjector는 파일명 파싱 로직을 격리하여 유지 중이나, 본 건은 GripResultProjector의 검증 단계에서 차단됨.

### Decision Drivers
- 데이터 처리 연속성 (배치 중단 방지)
- 검증 엄격도 유지 여부 (결함 데이터 숨김 방지)
- 재투영 비용 및 커서 관리 용이성
- 유지보수 부담 (스키마 vs 프로젝트터 격리)

### Considered Options
#### toyDataSchema 필드 옵셔널화 및 null 허용
- 접근: src/insert/dto/toy-data.dto.ts에서 grip_data, robot_tf에 .optional() 적용. GripResultProjector.map()에서 null일 때 DB 컬럼에 null 매핑.
- 제안 필드: grip_data, robot_tf, read_grip_result.grip2dPose, read_grip_result.robotTf
- 트레이드오프: 검증 엄격도 하락 but 처리 연속성 확보. 재투영 용이.
```typescript
const gripDataSchema = z.object({ grip_2d_pose: grip2dPoseSchema, grip_3d_pose: grip3dPoseSchema }).optional(); const robotTfSchema = z.object({ rotation_3x3: z.array(z.number()).length(9), translation_3x1: z.array(z.number()).length(3) }).optional(); return { ..., grip2dPose: payload.grip_data?.grip_2d_pose ?? null, robotTf: payload.robot_tf ?? null, ... };
```

#### Projector 매핑 단계 디폴트 객체 주입
- 접근: GripResultProjector.map() 내에서 검증 전 디폴트 객체로 치환.
- 제안 필드: GripResultProjector.map 로직
- 트레이드오프: 스키마 변경 없이 격리 but 디폴트 값이 실제 데이터와 혼동될 수 있음. Driver 검증 엄격도 유지 여부에서 졌음.
```typescript
const safePayload = { ...payload, grip_data: payload.grip_data ?? { grip_2d_pose: {}, grip_3d_pose: {} }, robot_tf: payload.robot_tf ?? { rotation_3x3: [], translation_3x1: [] } };
```

#### 신규 분리 Read Model
- 접근: read_grip_result_partial 생성.
- 제안 필드: 신규 테이블 스키마, 프로젝터 분리
- 트레이드오프: 유지보수 부담, 버전 관리 복잡성. Driver 유지보수 부담에서 졌음.

### Decision Outcome
toyDataSchema 필드 옵셔널화 및 null 허용

### Consequences
- (+) 결함 이벤트가 배치 처리를 중단시키지 않아 전체 적재 연속성 확보.
- (+) read_grip_result 컬럼이 null로 투영되어 결함 존재가 명시적으로 추적 가능.
- (+) 재투영 시 커서 이동이 원활하며, 별도 격리 테이블 관리 부담 없음.
- (−) Zod 검증 엄격도가 하락하여 누락 필드에 대한 즉시 알림이 지연될 수 있음.
- (−) null 허용으로 인해 하위 조회 로직에서 null 체크 추가 필요.

### Non-Goals

## 3. API Versioning

### 버전 영향

변경 없음. DTO 내부 검증 규칙 변경이며, Read Model 컬럼 타입(jsonb)과 엔드포인트는 불변. null 허용은 하위 호환성을 해치지 않으며, 기존 조회 API는 null 값을 정상적으로 반환함.
