## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → Zod 검증 실패로 원천 파일의 필수 필드(grip_data) 누락/타입 위반 드러남. [corr:65171de5-9d77-4176-8c20-e8cb3ae415d1]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → Zod 검증 실패로 원천 파일의 필수 필드(robot_tf) 누락/타입 위반 드러남. [corr:65171de5-9d77-4176-8c20-e8cb3ae415d1]
- src/insert/dto/toy-data.dto.ts 의 toyDataSchema 는 grip_data 와 robot_tf 가 필수(z.object) 로 정의되어 있어 Zod parse() 실패 시 적재 단계(insert.file.failed) 에서 이벤트 append 가 차단된다. [corr:65171de5-9d77-4176-8c20-e8cb3ae415d1]
- GripResultProjector.map() 의 try-catch 블록에서 parse() 실패 시 throw err 가 발생하여 투영이 건너뛰지만, 결함 이벤트는 event_store 에 유입되지 않아 Read Model(read_grip_result, read_multimodal) 구조에는 영향이 없다. [corr:65171de5-9d77-4176-8c20-e8cb3ae415d1]
- 이상 로그의 detail 필드(file=..._02004_01_...) 와 reason 배열을 대조해, Zod 거절이 원천 데이터 결결에 따른 시스템 의도된 방어 동작이며 Read Model 보강이 아닌 원천 데이터 수정 요청 lane 이다. [corr:65171de5-9d77-4176-8c20-e8cb3ae415d1]

### Decision Drivers
- Zod 거절은 시스템 의도된 방어 동작 (원천 데이터 검증)
- Read Model 구조 무해화 필요 없음 (이벤트 미유입)
- 원천 파일 필드 결결 원인 추적 및 재적재 준비

### Considered Options
#### sourceDataFixRequest
- 접근: Zod 검증 유지 + 원천 JSON 파일 필드 보강 요청(권장)
- 제안 필드: toy-data.dto.ts 스키마 미수정, 원천 데이터 파이프라인 수정
- 트레이드오프: 코드 변경 리스크 제로, 단 외부 CI/ETL 스크プト 의존성 발생으로 재적재 지연 가능.
```typescript
const payload = toyDataSchema.parse(event.payload); // Zod strictness 유지. 실패 시 throw err → insert.file.failed 로그 방출.
```

#### validationAuditLog
- 접근: `insert.file.failed` 로깅 보강으로 결함 파일 경로 매니스트 자동 생성
- 제안 필드: src/insert/insert.service.ts failHandler
- 트레이드오프: 미 Logging overhead 추가, 원천 데이터 품질 문제 식의성 및 batch 재적재 준비 용이.
```typescript
if (err instanceof z.ZodError) { logger.warn({ action: LogAction.FILE_FAILED, file: event.payload?.fileName }, 'Zod 거절 → 원천 데이터 결결'); auditManifest.push(event.payload.fileName); }
```

### Decision Outcome
sourceDataFixRequest

### Consequences
- (+) 이벤트 저장 오염 방지, Read Model 정합성 유지
- (+) Zod 검증 실패 로그(insert.file.failed)로 원천 데이터 품질 문제 즉시 식별
- (+) 무유입 검증 SQL 로 적재 단계 격리 확인 절차 확립
- (−) 원천 JSON 파일 수정/보완 작업이 외부 파이프라인 또는 CI 스크プト 의존성 발생
- (−) 재적재 실패 시 동일한 insert.file.failed 로그 반복 (고무줄 현저)

### Non-Goals
- Zod 스키마 완화(optional 화) 또는 z.coerce/기본값 주입으로 적재 통과
- 신규 추적 테이블 또는 Read Model 컬럼 추가
- 결함 이벤트가 event_store 에 append 되거나 투영 실패(poison event) 처리
