### Decision Drivers
- Data Integrity Guarantee (Zod 거절은 시스템 의도된 방어 동작)
- Zero Projection Schema Mutation (Read Model 구조·컬럼 무수변)
- Auditability of Rejected Batches (event_store 미적립 가시성 확보)

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청
- 접근: src/insert/dto/toy-data.dto.ts Zod 스키마(grip_succeed) 그대로 유지, 적재 실패 파일은 event_store 미적립 원칙으로 처리. upstream 데이터 수정 요청.
- 제안 필드: toyDataSchema.grip_succeed, insert.service.ts batch audit
- 트레이드오프: 재투영 비용 0, Read Model 순도 보장, 단 원천 파일 수정 인바운드 지연 발생.
```typescript
// toyDataSchema.grip_succeed: z.number().int().min(0).max(1) 유지. Zod 거절은 시스템 의도된 방어 동작. upstream file correction required.
```

#### 무유입 검증 절차
- 접근: 적재 batch 완료(insert.batch.done) 후 event_store 미적립 확인 SQL 실행으로 격리 가시성 확보.
- 제안 필드: containmentSql verification, event_store audit query
- 트레이드오프: DB overhead 소량 발생, phantom event 유입 차단 확실, Read Model 무수변.
```typescript
SELECT count(*) FROM event_store WHERE stream_id = 'grip-attempt:02002' AND attempt_num = 1; -- 기대값 0
```

### Decision Outcome
거절 유지 + 원천 데이터 수정 요청

### Consequences
- (+) Read Model(read_grip_result, read_multimodal) 이 순수한 정합성 데이터만 적재됨.
- (+) Zod 거절은 시스템 의도된 방어 동작으로 downstream projection pipeline 이 unaffected.
- (−) upstream 원천 파일 수정 인바운드 지연 발생.
- (−) batch completion time 소폭 연연 due to audit verification step.

### Non-Goals
- Zod 스키마 완화(optional 화) 또는 z.coerce/기본값 치환으로 적재 통과 우회.
- 결함 추적용 신규 테이블(read_model_audit 등) 추가.
- projector-level 정합성 검사(checkIntegrity) 수정으로 Zod 거절 대응.
