- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → 원천 JSON의 grip_succeed 필드 값이 1 초과로 유입되어 Zod max(1) 검증에 거절 (필수 필드/타입 위반). [corr:f63b98d7-0fdf-478d-b4e9-9b30dc2016f7]
- src/insert/dto/toy-data.dto.ts 의 toyDataSchema 정의는 grip_succeed: z.number().int().min(0).max(1) 로 엄격히 타입·범위를 강제한다. Zod 거절(insert.file.failed) 은 시스템이 의도한 방어 동작이며, 결함 이벤트는 event_store 에 미유입된 상태이다. [corr:f63b98d7-0fdf-478d-b4e9-9b30dc2016f7]
- GripAttemptRecorded Insight 카드의 grip_succeed:number 의미는 파지 성공 여부(0=실패, 1=성공) 이며, 원천 파일의 타입·범위 위반이 전적 단계에서 차단됨. Read Model(read_grip_result, read_multimodal) 구조는 정상 유지된다. [corr:f63b98d7-0fdf-478d-b4e9-9b30dc2016f7]
- GripResultProjector.map() 의 toyDataSchema.parse(event.payload) 호출은 이미 적재 단계에서 실패 경로로 진입하지, 투영 로직(catchUpAll) 은 insert.batch.done 이후 정상 커서 전진으로 진행됨. [corr:f63b98d7-0fdf-478d-b4e9-9b30dc2016f7]
- read_grip_result 스키마의 grip_succeed:smallint 컬럼은 투영된 데이터만 적재되나, Zod 거절로 인해 해당 원천 파일은 skip 처리되어 Read Model 오염이 발생하지. [corr:f63b98d7-0fdf-478d-b4e9-9b30dc2016f7]

### Decision Drivers
- 데이터 무해화 원칙: Zod 거절된 값(타입 위반·범위 밖) 은 z.coerce/기본값 치환으로 Read Model 유입 권고 금지.
- 적재 vs 투영 분리: insert.file.failed 는 ingestion stage 차단, projection stage 무관.
- Operational visibility: operator 가 결함 파일 이력 추적 및 upstream 수정 요청 안내 용이해야.

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청
- 접근: src/insert/dto/toy-data.dto.ts 의 Zod 스키마(grip_succeed) 는 현 strict 검증(z.number().int().min(0).max(1)) 을 그대로 유지. 결함 파일은 적재 단계에서 skip 처리하며, upstream 원천 JSON 수정 요청을 통으로 안내.
- 제안 필드: src/insert/dto/toy-data.dto.ts, upstream_data_pipeline
- 트레이드오프: 재투영·비용 리스크 제로. 데이터 무해화 원칙 준수. 다만 upstream 의사소통이 필요한 오버헤드 발생.


- 접근: src/insert/insert.service.ts 의 적재 완료 로직 보강하여 failedFileCount > 0 시 batch-level 검증 SQL 실행으로 event_store 미유입 확인. downstream projection runner 가 정상 커서 전진 보장.
