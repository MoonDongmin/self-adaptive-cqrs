### Decision Drivers
- batch transaction integrity preservation
- read model schema stability
- source data defect handling policy (reject vs coerce)
- operational overhead tolerance

### Considered Options
#### Skip & Cursor Advance (Poison Event Skip)
- 접근: GripResultProjector.map() 또는 CatchUpRunner batch loop 수정. 결함 이벤트 식별 시 throw 대신 skip signal 반환, 커서 전진 SQL 실행.
- 제안 필드: skipLogic, cursorAdvanceSql
- 트레이드오프: 추가 로직/DB 호출 오버헤드 발생, but batch integrity 보장.
```typescript
try { row = projector.map(event); } catch (err) { if (isDefectPayload(err)) { await advanceCursor(tx, event.eventId); logger.skip(...); continue; } throw err; }
```

#### Dead Letter Insert (Quarantine Table)
- 접근: GripResultProjector.map() 예전 포착 시 read_grip_result 에 플래그 컬럼(is_defect, object_name='DEFECT') 삽입.
- 제안 필드: quarantineFlag, deadLetterInsert
- 트레이드오프: Read Model 테이블 용량 증가, downstream 조회 시 필터링 필요, but 트랜잭션 커밋 유지.
```typescript
try { row = projector.map(event); } catch (err) { if (isDefectPayload(err)) { await tx.insert(readGripResult).values({ sceneKey: event.streamId.replace(/^grip-attempt:/, ''), attemptNum: event.attemptNum, objectName: 'DEFECT', gripSucceed: 0, gripperType: 'finger', occurredAt: event.occurredAt, streamId: event.streamId, globalSeq: event.globalSeq }); logger.quarantine(...); continue; } throw err; }
```

### Decision Outcome

### Consequences
- (+) Batch rollback 차단, 정상 이벤트 투영 유지 보장.
- (+) 원천 데이터 격리 정책 준수.
