- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → 원천 파일의 필수 필드 누락/타입 위반 (grip_succeed >1 위상) [corr:4dff96a4-3202-4736-aea2-37965e1aa67d]
- src/insert/dto/toy-data.dto.ts Zod 스키마 grip_succeed: z.number().int().min(0).max(1) 이 적재 검증 실패 원천.
- Insight 카드 read_grip_result.grip_succeed(smallint) 와 read_multimodal.image_2d_uri(text) 는 Read Model 컬럼·의미가 정상이나 원천 데이터 품질 issue 가 발생한 시나리오다.
- src/projection/projector/multimodal.projector.ts 의 map() 메서드에서 image2dUri 와 videoUri 는 현재 null로 둠, 투영된 Read Model 구조는 정상이나 원천 데이터 품질 issue 가 발생한 시나리오다.

### Decision Drivers
- 원천 데이터 품질 보장 (Zod 거절은 시스템 의도한 방어 동작)
- 시스템 스키마 안정성 유지 (Read Model/Event Store schema 불변)
- 운영 비용 최소화 (저과head verification/alert)
- 격리 검증 절차 신뢰도 (무유입 확인 + 원천 수정 요청 연계)

### Considered Options
#### 거절 유지 + 원천 수정 요청
- 접근: Zod strictness 유지, 실패 파일에 대한 원천 데이터 수정 요청 trigger.
- 제안 필드: src/insert/dto/toy-data.dto.ts 검증 로직, InsertService 실패 알림 dispatch
- 트레이드오프: Zero schema impact, data integrity guaranteed, but requires external source correction workflow.
```typescript
this.logger.warn({ action: LogAction.SOURCE_DATA_CORRECTION_REQUEST, streamId: event.streamId, reason: err.message }, "원천 데이터 수정 요청 trigger");
```

#### 무유입 검증 절차
- 접근: Batch 완료 후 SQL verification query 실행해 event_store 누수 확인.
- 제안 필드: InsertService post-batch verification hook, containmentSql execution
- 트레이드오프: Low overhead, guarantees consistency, but adds minor sync check latency.
```typescript
const verifyResult = await db.run(`SELECT count(*) FROM event_store WHERE stream_id = 'grip-attempt:${sceneKey}' AND attempt_num = ${attemptNum};`); if (verifyResult[0].count !== 0) throw new Error("Leak detected");
```

#### 기각 대안: Zod 완화/Default 주입
- 접근: Zod 스키마 변경으로 적재 통과.
- 제안 필드: src/insert/dto/toy-data.dto.ts coercion
- 트레이드오프: Failed against Driver 1 & 2. 검증에 거절된 값을 정상값처럼 꾸며 Read Model 에 유입시키는 권고는 원칙 위반으로 기각 대안.

### Decision Outcome
무유입 검증 절차 + 원천 수정 요청 — Zod 거절은 시스템이 의도한 방어 동작이며, 무유입 SQL verification을 먼저 실행해 event_store 누수를 확정하고, 실패 파일에 대한 원천 데이터 수정 요청을 trigger하는 lane 이 가장 직접하게 해결하는 권고다.

### Consequences
- (+) Data integrity preserved (Zod strictness 유지)
- (+) No schema drift or Read Model structure modification
- (+) Batch processing unaffected by file-level try/catch policy
- (−) Requires external source data correction workflow coordination
- (−) Temporary monitoring overhead for failed files until source fix confirmed

### Non-Goals
- Schema modification (Read Model/Event Store)
- Zod coercion or default value injection to pass validation
- New table creation for defect tracking
