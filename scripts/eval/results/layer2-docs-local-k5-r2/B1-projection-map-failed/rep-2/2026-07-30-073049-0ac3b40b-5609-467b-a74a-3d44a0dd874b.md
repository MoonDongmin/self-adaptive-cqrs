### Context (근거)

- (level 50, `db.error`) 투영 트랜잭션 실패 → db.error(트랜잭션 실패)로 인해 catch-up batch rollback이 발생하며 정상 매핑 이벤트까지 유동 상태. [corr:0ac3b40b-5609-467b-a74a-3d44a0dd874b]
- GripAttemptRecorded 스키마의 objects[].annotation_type:string... 배열 필드는 Read Model의 object_name:varchar 매핑 원천. 빈 배열 시 payload.objects[0].class_name 접근 실패.
- src/projection/projector/grip-result.projector.ts 42줄에서 if (payload.objects.length === 0) { throw new Error(...) } 로직이 결함 payload를 fatal exception으로 정의, 배치 트랜잭션 롤백을 유발.
- read_grip_result 스키마의 object_name:varchar 컬럼은 payload.objects[0].class_name 매핑 시점, 빈 배열 접근 시 undefined/throw 발생.

### Decision Drivers
- Batch transaction safety: 단일 결함 이벤트가 전체 batch 롤백 차단해야 한다.
- Data fidelity preservation: 검증에 거절된 값은 정답으로 격리·유지 + 원천 수정 요청이다.
- Pipeline standardization: projector contract(map/checkIntegrity) 일관성 확립.
- Operational overhead minimization: 추가 연동 로직은 minimal 해야 한다.

### Considered Options
#### Dead-letter Skip
- 접근: GripResultProjector.map() 수정으로 empty objects 판정 시 fatal throw 제거 → warning log emission + null/skip marker 반환.
- 제안 필드: map(), logger.warn
- 트레이드오프: 데이터 유입 단절(해당 시도 기록 누락) but batch rollback 차단. 기각 대안: Driver 3(Pipeline standardization)에서 기존 Projector<Insert> contract 위이므로 runner layer exception handling 연동 필요, overhead 증가.
```typescript
if (payload.objects.length === 0) { this.logger.warn({ action: LogAction.MAP_FAILED, [LogContext.EVENT_ID]: event.eventId }, "objects 비어 있음 ← dead-letter"); return null; }
```

#### IntegrityViolation Return
- 접근: GripResultProjector.checkIntegrity() 메서드 추가하여 objects.length === 0 판정 시 IntegrityViolation[] 반환 → CatchUpRunner에서 violation 발생 시 event skip + 격리 로그 emission.
- 제안 필드: checkIntegrity, runner.skipLogic
- 트레이드오프: runner 연동 필요 but 기존 projector contract 확립 및 표준 에러 처리 정책 적용. 권장 대안: Driver 3(standardization)와 Driver 1(safety) 동호 충족, existing MultiModalProjector.checkIntegrity 패턴 확장으로 minimal overhead.
