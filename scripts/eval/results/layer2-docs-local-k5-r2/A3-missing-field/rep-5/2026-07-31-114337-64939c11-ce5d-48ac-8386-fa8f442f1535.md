## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → 원천 payload의 필수 필드(grip_data) 누락으로 Zod 검증이 거절, 이벤트는 event_store 미적재됨. [corr:64939c11-ce5d-48ac-8386-fa8f442f1535]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → 원천 payload의 필수 필드(robot_tf) 누락으로 Zod 검증이 거절, 이벤트는 event_store 미적재됨. [corr:64939c11-ce5d-48ac-8386-fa8f442f1535]
- Insight 카드 read_grip_result 의 grip_2d_pose(jsonb, 2D 파지점) 및 robot_tf(jsonb, 로봇 변환행렬) 컬럼은 원천 payload 의 grip_data/robot_tf 객체를 매핑.
- 소스 src/insert/dto/toy-data.dto.ts 의 toyDataSchema 정의에서 grip_data: gripDataSchema 및 robot_tf: robotTfSchema 가 필수(z.object() 등) 로 강제.
- GripResultProjector.map() 호출 시 toyDataSchema.parse(event.payload) 가 실패 시 throw error, 하지만 실제 적재 계층 은 파일 단위 try/catch 로 격어 실패된 파일만 event_store 미적재할 뿐.
- 결과: Read Model 구조는 정상, 결함은 원천 데이터 누락. 투영 정지/롤백 발생하지.

### Decision Drivers
- 원천 데이터 결함 vs Read Model 구조 구분
- Zod 의도된 방어 동작 유지
- 미유입 격리 확증 필요
- API/Schema 변경 최소화

### Considered Options
#### 거절 유지 + 원천 데이터 수정 요청
- 접근: Zod 검증(toyDataSchema) 유지, 미적재된 파일에 대한 원천 데이터 보강/수정 요청 프로세스 도입.
- 제안 필드: src/insert/dto/toy-data.dto.ts, src/projection/projector/grip-result.projector.ts
- 트레이드오프: 재투영 비용 0, 리스크 원천 데이터 수정 지연.
```typescript
// Zod 검증 유지. 미적재 파일 추적 로직 도입: if (!event.payload) { logger.warn('zod_rejected'); return; }
```

#### 무유입 검증 절차
- 접근: 적재 실패 로그(insert.file.failed) 발생 시, 해당 scene_key/attempt_num 에 대한 event_store 미유입을 SQL 로 검증하여 격리 상태 확정.
- 제안 필드: containmentSql 필드 추가, 검증 서비스 도입
- 트레이드오프: DB 조회 오버헤드 소량, 리스크 무해화 보장.
```typescript
const verifyNoLoad = async (sceneKey, attemptNum) => { const rows = await db.select(eventStore).where(eq(streamId, 'grip-attempt:' + sceneKey)).and(eq(attemptNum, attemptNum)); return rows.length === 0; };
```

### Decision Outcome
거절 유지 + 원천 데이터 수정 요청

### Consequences
- (+) Zod 검증 신뢰도 유지
- (+) Read Model 오염 방지
- (+) 무해화 원칙 준수
- (−) 원천 데이터 수정 지연 시 투영 누락 발생(의도된 동작)
- (−) 추가 운영 프로세스 필요

### Non-Goals
- Zod 스키마 완화/optional 화
- default value 주입
- 신규 추적 테이블 도입
