## 1. 권고 (Recommendation)

### Context (근거)
- (level 50, `projection.map.failed`) objects 비어 있음 → 기존 Read Model인 `read_grip_result`에서 `objects` 필드가 비어 있어 투영이 실패함을 드러냄 [corr:1a1227ca-777b-48c4-82c9-504a25ac0f48]
- Insight 카드에 따르면 `GripAttemptRecorded` 이벤트의 `objects` 필드는 필수이며, 이 필드가 비어 있으면 `read_grip_result`에 투영할 수 없음.
- `GripResultProjector`의 `map` 메서드에서 `payload.objects.length === 0` 조건이 참일 경우, 'objects 비어 있음' 로그를 남기고 에러를 발생시킴. 이는 `src/projection/projector/grip-result.projector.ts`의 42-50행에서 확인됨.
- `read_grip_result` 테이블의 `object_name` 필드는 `payload.objects[0].class_name`으로 매핑되며, `objects`가 비어 있으면 이 필드에 값이 할당되지 않음. 이는 `src/shared/database/schema/service/read-grip-result.ts`의 스키마 정의에서 확인됨.

### Decision Drivers
- 투영 실패 방지
- 기존 데이터 무결성 유지
- 오류 기록 및 분석 가능성

### Considered Options
#### 투영 건너뛰기
- 접근: GripResultProjector의 map 메서드에서 objects가 비어 있을 경우, 해당 이벤트를 건너뛰도록 수정.
- 제안 필드: map 메서드 수정
- 트레이드오프: 이 방법은 투영 실패를 방지하지만, 비어 있는 objects가 발생하는 원인을 해결하지 않으므로 근본적인 문제는 남아 있음.
```typescript
if (payload.objects.length === 0) { this.logger.warn({ action: LogAction.MAP_SKIPPED, [LogContext.EVENT_ID]: event.eventId, [LogContext.STREAM_ID]: event.streamId, }, 'objects 비어 있어 투영 건너뜀'); return null; }
```

#### 오류 기록
- 접근: GripResultProjector의 map 메서드에서 objects가 비어 있을 경우, 해당 이벤트를 별도의 오류 테이블에 기록.
- 제안 필드: 오류 테이블 생성, logErrorToDatabase 메서드
- 트레이드오프: 이 방법은 문제를 기록하여 추후 분석할 수 있지만, 투영은 여전히 실패함.
```typescript
if (payload.objects.length === 0) { await this.logErrorToDatabase(event); throw new Error(`grip-result map: empty objects in event ${event.eventId}`); }
```
