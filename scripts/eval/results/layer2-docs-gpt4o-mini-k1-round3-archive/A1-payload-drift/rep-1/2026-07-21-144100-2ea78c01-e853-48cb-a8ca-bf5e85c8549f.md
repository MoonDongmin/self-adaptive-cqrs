## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `payload.schema.drift`) payload 에 스키마가 모르는 신규 키 유입 — 적재 시 유실됨(Read Model 후보) ← 트립 앵커 → 기존 Read Model인 `read_grip_result`는 신규 키인 `conveyor_speed`와 `gripper_temperature`를 수용할 수 없어 요청을 충족하지 못함. [corr:2ea78c01-e853-48cb-a8ca-bf5e85c8549f]
- `read_grip_result`의 현재 스키마는 `conveyor_speed`와 `gripper_temperature`를 포함하지 않음.
- `src/shared/database/schema/service/read-grip-result.ts`에서 `readGripResult` 테이블 정의를 확인할 수 있으며, 신규 키가 반영되지 않음.
- `src/projection/projector/grip-result.projector.ts`의 `map` 메서드에서 `grip_succeed`, `grip_2d_pose`, `grip_3d_pose` 등 기존 필드만 처리하고 있어 신규 필드에 대한 처리가 없음.

### Decision Drivers
- 신규 키 수용 가능성
- 기존 데이터와의 호환성 유지
- API 버전 관리 필요성

### Considered Options
#### 신규 Read Model `read_grip_result_v2` 채택
- 접근: read_grip_result_v2 테이블을 생성하고, conveyor_speed와 gripper_temperature 필드를 추가하여 신규 Read Model을 구현.
- 제안 필드: conveyor_speed, gripper_temperature
- 트레이드오프: 신규 Read Model을 생성함으로써 기존 데이터와의 호환성을 유지하면서도 신규 키를 수용할 수 있음. 그러나 데이터 마이그레이션이 필요함.

### Decision Outcome
신규 Read Model `read_grip_result_v2` 채택 — 신규 키를 수용할 수 있는 유일한 방법.

### Consequences
- (+) 신규 키를 수용하여 데이터의 완전성을 유지할 수 있음.
- (+) 기존 데이터와의 호환성을 유지하면서도 새로운 요구사항을 충족할 수 있음.
- (−) 데이터 마이그레이션이 필요하여 추가 작업이 발생할 수 있음.

### Non-Goals
- 기존 Read Model의 구조적 변경은 지양함.
- 기존 데이터의 손실을 방지함.
