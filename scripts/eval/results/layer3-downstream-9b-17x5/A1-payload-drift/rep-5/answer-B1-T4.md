제공된 자료 (로그 컨텍스트, Read Model 스키마) 에 따르면, 현재 시스템은 `payload.schema.drift` 로그를 발생시키고 있으며, 이는 스키마에 없는 신규 키 (`conveyor_speed`, `gripper_temperature`) 가 유입되어 Read Model 에 적재되지 않고 유실되는 '트립 앵커' 현상을 일으키고 있습니다.

하지만 **제공된 자료에는 기존 API 의 버전 (v1), 새로운 API 의 버전, 또는 버전 관리 전략에 대한 정보가 전혀 포함되어 있지 않습니다.**

따라서 "기존 v1 API 클라이언트가 깨지지 않게 하려면"이라는 전제 조건 하에 구체적인 버전 경로, 병행 운영, 마이그레이션 절차를 작성하는 것은 **자료에 없는 사실을 지어내는 것**이 됩니다.

제약 조건 ("자료에 없는 사실은 지어내지 마라") 에 따라, 현재 자료만 근거로 할 수 있는 답변은 다음과 같습니다.

```text
제공된 자료 (<logging_context>, <insight_read_db>) 에는 기존 API 의 버전 (예: v1), 새로운 API 의 버전 (예: v2), 또는 버전 관리 전략에 대한 정보가 포함되어 있지 않습니다. 따라서 자료에 근거하여 구체적인 버전 경로, 신구 병행 운영, 마이그레이션 절차를 작성할 수 없습니다.

해결을 위해서는 기존 API 의 버전 정보와 변경 사항이 반영된 새로운 API 의 명세를 추가로 제공해야 합니다.
```
