제시된 자료에 따르면, `반려동물용품_CR01_강아지공룡알장난감_02018` 과 `반려동물용품_CR01_강아지공룡알장난감_02019` 에 대해 `gripSucceed=1` 이지만, 모든 `grip3dPose` 의 `z` 좌표가 물리 하한 `0.01m` 보다 작아 파지 불가능한 모순이 발생했습니다.

기존 Read Model (`read_grip_result`) 에는 `grip_3d_pose` 필드가 존재하지만, 이를 검증하기 위해 `robot_tf` (로봇 변환 행렬) 와 `workspace` (작업 공간) 정보가 필요합니다. 자료의 `<logging_context>` 에는 `robotTf` 가 포함되어 있으나, 워크스페이스 범위 `[0.95, 1.15]` m 은 자료에 명시된 상수이며, 로봇 변환 행렬을 통해 센서 좌표를 월드 좌표로 변환하여 워크스페이스 범위와 비교하는 로직이 필요합니다.

따라서, 파지 성공 여부 (`grip_succeed`) 와 물리적 깊이 (`z` 좌표) 가 워크스페이스 및 로봇 변환에 의해 계산된 실제 깊이의 일관성을 검증하는 새 Read Model 테이블 `read_grip_consistency` 를 생성하고, 해당 데이터를 채우는 SQL 을 작성합니다.

### 1. 새 Read Model 테이블 생성 (DDL)

```sql
CREATE TABLE IF NOT EXISTS read_grip_consistency (
    scene_key VARCHAR PRIMARY KEY,
    attempt_num SMALLINT NOT NULL,
    object_name VARCHAR NOT NULL,
    grip_succeed SMALLINT NOT NULL,
    min_grip_z REAL NOT NULL,
    workspace_min_z REAL NOT NULL DEFAULT 0.95,
    workspace_max_z REAL NOT NULL DEFAULT 1.15,
    physical_min_z REAL NOT NULL DEFAULT 0.01,
    is_consistent BOOLEAN NOT NULL DEFAULT TRUE,
    consistency_reason TEXT,
    created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### 2. 데이터 검증 및 삽입 SQL

이 SQL 은 `read_grip_result` 테이블에서 데이터를 조회하여, `robot_tf` 를 이용해 `grip_3d_pose` 의 z 좌표를 월드 좌표로 변환하고, 워크스페이스 범위와 물리적 하한을 비교하여 일관성 (`is_consistent`) 을 판단한 후, `read_grip_consistency` 테이블에 삽입합니다.
