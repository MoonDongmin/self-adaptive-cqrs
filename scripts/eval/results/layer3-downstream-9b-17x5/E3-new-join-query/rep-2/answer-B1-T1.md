사용자가 파지 결과와 해당 시도의 이미지·영상 경로를 한 화면에 함께 표시하려는 조회 요청을 수행했으나, `insight.card.request` 로그에 "파지 결과와 해당 시도의 이미지·영상 경로를 한 화면에서 함께 보고 싶다"라는 상세 메시지가 기록된 바와 같이, 기존 Read Model 구조로는 이 요구사항을 충족할 수 없는 문제가 발생했습니다.

원인은 `read_grip_result`와 `read_multimodal` 테이블이 각각 `(scene_key, attempt_num)` 키로 독립적으로 정의되어 있어, 두 데이터 소스를 단일 쿼리에서 조인하거나 동시 조회하는 메커니즘이 Read Model 레이어에 구현되어 있지 않기 때문입니다.

구체적으로 `read_grip_result`는 파지 성공 여부 (`grip_succeed`) 및 포즈 정보 (`grip_2d_pose`) 를 저장하고, `read_multimodal`은 이미지 URI(`image_2d_uri`) 및 비디오 URI(`video_uri`) 를 저장하고 있으나, 두 테이블 간에 필드별 직접적인 연결 관계가 정의되어 있지 않습니다.

따라서 사용자가 요청한 "한 화면에서 함께 보고 싶다"는 조건을 만족시키기 위해서는, 현재 `read_grip_result`와 `read_multimodal`의 키 구조가 동일하므로 SQL 조인 (`JOIN`) 을 통해 두 테이블을 연결하는 새로운 조회 로직이 필요하지만, 이는 현재 제공된 자료에 명시된 Read Model 스키마만으로는 불가능한 상태입니다.

결론적으로, 이미지/영상 경로 필드가 파지 결과 테이블에 포함되지 않았고, 별도의 미디어 조회 테이블이 존재하므로 단일 조회 API 로 두 정보를 통합하여 반환할 수 없는 구조적 한계가 원인입니다.
