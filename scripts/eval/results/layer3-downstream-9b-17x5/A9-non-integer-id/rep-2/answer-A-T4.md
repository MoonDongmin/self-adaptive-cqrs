제공된 자료에 따르면, 이번 변경은 **Read Model 생성 SQL**이 필요하지 않으며, **격리 (Containment) SQL**만 실행하여 Zod 검증으로 인해 적재되지 않은 이벤트가 이벤트 스토어에 유입되지 않았음을 확인하는 단계입니다.

자료의 'Decision Outcome'에 따르면 "Read Model 생성 SQL ... 불필요, 결함 데이터 무해화가 조치다"라고 명시되어 있습니다. 따라서 기존 v1 API 클라이언트가 깨지지 않게 하려면 **API 버전 변경이나 새로운 엔드포인트 추가 없이, 기존 API 로직을 유지**하는 것이 유일한 해결책입니다.

구체적 단계는 다음과 같습니다:

1.  **버전 경로 (Version Path) 변경 없음**:
    *   자료에 따르면 "API 버전 변경 없음"입니다.
    *   기존 v1 API 클라이언트는 현재 사용 중인 엔드포인트 (예: `/api/v1/read_grip_result`) 를 그대로 호출하며, 응답 구조도 변경되지 않습니다.
    *   새로운 API 버전 (예: `/api/v2/...`) 을 생성하거나 기존 경로를 리디렉션하지 않습니다.

2.  **신구 병행 운영 (Parallel Operation) 불필요**:
    *   새로운 Read Model 테이블을 생성하거나, 기존 테이블을 수정하는 DDL이 실행되지 않습니다.
    *   따라서 기존 v1 API 가 의존하는 데이터 소스 (Read Model) 가 물리적으로 사라지거나 구조가 바뀌는 상황이 발생하지 않습니다.

3.  **마이그레이션 및 컷오버 절차**:
    *   **DDL 실행**: 없음 (Read Model 생성 SQL 생략).
    *   **데이터 마이그레이션**: 없음 (기존 데이터 구조 변경 없음).
    *   **컷오버 (Cutover)**:
        *   격리 SQL (`SELECT count(*) ...`) 만 실행하여 검증된 후, 해당 쿼리 결과가 기대값 (0) 과 일치하면 **인간 승인**을 받습니다.
        *   인간 승인이 완료되면, **아무런 코드 변경 없이** 기존 v1 API 를 계속 운영합니다.
        *   API 컷오버는 인간 승인 후에도 필요 없습니다.

**요약**:
기존 v1 API 클라이언트가 깨지지 않게 하려면 **어떤 코드 변경도, 어떤 DDL 실행도, 어떤 API 컷오버도 수행하지 않고, 현재 상태를 그대로 유지**하는 것입니다. 제공된 자료의 권고 사항이 "결함 데이터 무해화" (유입되지 않은 데이터만 확인) 에 국한되어 있기 때문입니다.

```sql
-- [격리 단계] 인간 승인 후 실행
SELECT count(*) AS rejected_event_count 
FROM event_store 
WHERE (stream_id, attempt_num) IN (
    ('grip-attempt:반려동물용품_CR01_강아지공룡알장난감_02022', 1), 
    ('grip-attempt:반려동물용품_CR01_강아지공룡알장난감_02023', 1)
);
```
