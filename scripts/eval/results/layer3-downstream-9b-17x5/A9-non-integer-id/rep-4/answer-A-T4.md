제공된 자료에 따르면, 이번 변경은 **Read Model 테이블 구조 변경**이나 **API 엔드포인트 변경**이 아닌, **원천 데이터 (Payload) 의 타입 정제**와 **적재 실패 파일의 무해화 (무투영)**에 국한됩니다.

1.  **Read Model 무손상**: `read_grip_result` 및 `read_multimodal` 테이블 스키마는 변경되지 않으며, PK 구조도 유지됩니다.
2.  **API 무변**: API 엔드포인트 목록 (`affectedEndpoints: []`) 이 비어있고, API 스펙은 유지됩니다.
3.  **데이터 손실**: Zod 검증 실패로 인해 특정 파일 (scene_key: `반려동물용품_CR01_강아지공룡알장난감_02022`, `02023`) 의 이벤트가 `event_store` 에 추가되지 않으므로, 해당 키에 대한 Read Model 데이터는 생성되지 않습니다. 이는 기존 v1 API 클라이언트가 데이터를 조회할 때 해당 키에 대한 결과가 없을 뿐, API 응답 형식이나 경로가 깨지는 것은 아닙니다.

따라서 **버전 경로 변경, 신구 병행 운영, 마이그레이션 절차는 모두 불필요**하며, 기존 v1 API 클라이언트는 **즉시 정상 작동**합니다.

### 구체적 단계

1.  **버전 경로**: 변경 없음 (`/api/v1` 유지).
2.  **신구 병행 운영**: 불필요함 (기존 스키마 유지).
3.  **마이그레이션 및 컷오버 절차**: 불필요함 (DDL 실행 없음).
