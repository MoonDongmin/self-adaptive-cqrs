사용자가 일자별 파지 성공률 추이 (시도 수, 성공 수, 성공률) 를 시간 순으로 조회했으나, `insight.card.miss` 로그가 반복되어 요청이 실패했습니다. 이는 `read_daily_grip_stats_v1`이라는 Read Model 테이블이 현재 DB 스키마에 존재하지 않아 구조적 부재로 인한 문제입니다. 기존 `read_grip_result` 테이블은 `(scene_key, attempt_num)` 을 Primary Key 로 하는 행 단위 (row-level) 스키마로 설계되어 있어, `occurred_at` 기준으로 `GROUP BY` 하는 집계 연산이 불가능합니다. 또한 `GripResultProjector` 는 단일 이벤트 매핑만 담당하고 있어, `total_attempts` 와 같은 집계 필드를 생성하는 로직이 구현되지 않았습니다. 따라서 사용자 요청을 충족시키기 위해 `read_daily_grip_stats_v1` 테이블을 새로 생성하고, 이를 집계하는 `DailyGripStatsProjector` 를 구현해야 합니다.
