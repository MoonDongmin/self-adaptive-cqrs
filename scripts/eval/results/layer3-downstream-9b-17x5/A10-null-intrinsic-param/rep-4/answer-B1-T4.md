제공된 자료 (로그 및 스키마) 에 따르면, 현재 시스템은 `insert.file.failed` 로직이 존재하며, Zod 검증 실패 시 해당 파일에 대한 이벤트가 ES 에 추가되지 않거나 (또는 별도 처리되지 않은) `read_grip_result` 와 `read_multimodal` 테이블에 해당 레코드가 생성되지 않는 것으로 보입니다.

자료에는 **v1 API 클라이언트의 구조, 기존 API 엔드포인트의 버전 관리 정책, 또는 마이그레이션 스크립트**에 대한 정보가 전혀 포함되어 있지 않습니다. 따라서 "기존 v1 API 클라이언트가 깨지지 않게 하려면"이라는 전제 조건을 자료에 근거하여 구체적 단계로 답변하는 것은 불가능합니다.

자료에 없는 사실 (예: API 버전 경로 규칙, 클라이언트 호환성 체크 방법, 마이그레이션 타임라인 등) 을 지어낼 수 없으므로, 요청하신 구체적인 단계별 답변을 작성할 수 없습니다.

**해결을 위해 필요한 추가 자료:**
1.  현재 운영 중인 v1 API 의 엔드포인트 경로 (예: `/api/v1/grip-results`) 와 반환 형식.
2.  새로운 변경 사항 (적재 실패 처리 로직) 이 API 응답에 어떻게 반영되어야 하는지 (예: `status: failed`, `error_code` 필드 추가 등) 의 설계안.
3.  API 버전 관리 전략 (예: `/api/v1/...` 유지 후 `/api/v2/...` 추가, 아니면 동적 헤더 처리 등).

이러한 정보가 제공되지 않는 한, 백엔드 엔지니어로서 자료에 근거한 구체적인 마이그레이션 절차를 제시할 수 없습니다.
