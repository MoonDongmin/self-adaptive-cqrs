## 1. 권고 (Recommendation)

### Status
proposed

### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → grip_data 누락으로 Zod 검증 실패하여 파일 적재 중단, Read Model 투영 파이프라인이 부분 누락 이벤트에 대한 소프트 폴백을 갖추지 못했음을 드러냄 [corr:7d7ad67b-00e6-4cad-9517-9a08505d4545]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → robot_tf 누락으로 Zod 검증 실패하여 파일 적재 중단, 배치 롤백 없이 완료되므로 실패 파일은 Read Model에 영구 누락됨 [corr:7d7ad67b-00e6-4cad-9517-9a08505d4545]
- src/insert/dto/toy-data.dto.ts의 toyDataSchema는 grip_data와 robot_tf를 옵셔널 없이 정의하여 누락 시 즉시 파싱 예외를 발생시킨다.
- src/projection/projector/grip-result.projector.ts의 GripResultProjector.map()은 검증 실패 시 즉시 예외를 던지며, 성공 시 payload.grip_data.grip_2d_pose 등 필드를 직접 참조해 read_grip_result의 grip2dPose, robotTf 컬럼에 매핑한다.
- src/shared/database/schema/service/read-grip-result.ts의 Drizzle 스키마에서 grip2dPose, robotTf는 .notNull() 없이 선언되어 DB 레벨에서 null 허용이 가능하나, 프로젝트 코드에서는 Zod 검증 실패로 인해 해당 컬럼에 null을 삽입할 경로가 차단된다.
- insert.file.failed 로그는 파일 단위 적재 실패를 나타내며, 전체 배치(insert.batch.done)가 롤백 없이 완료되므로 실패 파일은 Read Model에 영구 누락된다.

### Decision Drivers
- 배치 안정성: 일부 누락 이벤트로 인한 전체 적재 중단 방지
- Read Model 정합성: 누락 필드에 대한 명시적 상태(null) 관리 및 하위 조회 안정성
- 운영 오버헤드: 추가 격리 테이블/로직 도입 vs 기존 파이프라인 수정 비용

### Considered Options
#### LenientDtoAndProjectorFallback
- 접근: src/insert/dto/toy-data.dto.ts의 grip_data와 robot_tf를 .optional()로 변경하고, src/projection/projector/grip-result.projector.ts의 map()에서 null일 경우 DB 컬럼에 null을 매핑하도록 수정
- 제안 필드: grip_data, robot_tf
- 트레이드오프: 배치 성공률 향상, 코드 변경 최소화. Read Model에 null 값이 누적되어 하위 조회 시 별도 null 처리 필요.
```typescript
grip_data: gripDataSchema.optional(), robot_tf: robotTfSchema.optional() 및 grip2dPose: payload.grip_data?.grip_2d_pose ?? null, grip3dPose: payload.grip_data?.grip_3d_pose ?? null, robotTf: payload.robot_tf ?? null
```

#### StrictDtoWithQuarantineRoute
- 접근: 기존 Zod 검증 유지, src/insert/dto/toy-data.dto.ts의 parse 실패 시 src/projection/projector/grip-result.projector.ts에서 예외 던지지 않고 별도 quarantine 테이블로 분리하여 배치 진행
- 제안 필드: quarantine_log, insert_service_filter
- 트레이드오프: Read Model 정합성 완벽 유지. 삽입 서비스 레이어 수정 필요, 배치 지연 및 운영 오버헤드 증가.
```typescript
try { payload = toyDataSchema.parse(event.payload); } catch (error) { await tx.insert(quarantineTable).values({ ...event, reason: "missing_grip_data" }); return null; }
```

#### Rejected
- 접근: DB default constraint만 변경하여 Zod 예외 우회 시도
- 제안 필드: -
- 트레이드오프: Zod가 Drizzle insert 전에 throw하므로 적용 불가. 배치 안정성 및 검증 경계 준수에서 실패.

### Decision Outcome
LenientDtoAndProjectorFallback

### Consequences
- (+) 파일 단위 검증 실패로 인한 배치 중단 제거, 전체 적재 성공률 향상
- (+) read_grip_result의 null 허용 스키마와 코드 매핑 일치로 하위 조회 시 예외 발생 방지
- (+) 기존 Drizzle/Projector 구조 최소 수정으로 배포 리스크 감소

- (−) Zod 검증이 완화되므로 누락 데이터가 Read Model에 누적되어 추후 데이터 품질 모니터링 필요
