### Context (근거)
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 ← 트립 앵커 → toyDataSchema의 grip_succeed 필드가 문자열 타입 및 1 초과 값으로 인해 Zod 검증에서 거부되며, 해당 이벤트가 Event Store에 기록되지 않아 read_grip_result Read Model 갱신이 차단됨을 드러냄 [corr:76be74f8-fdde-4eed-9e67-de798dcd2215]
- (level 40, `insert.file.failed`) toy-data 파일 적재 실패 → 배치 처리 중 단일 파일의 검증 실패가 전체 적재 흐름을 트립 앵커로 작용하여 하류 투영이 중단됨 [corr:76be74f8-fdde-4eed-9e67-de798dcd2215]
- src/insert/dto/toy-data.dto.ts의 toyDataSchema는 grip_succeed: z.number().int().min(0).max(1)으로 엄격하게 정의되어 있어, 입력 페이로드의 문자열/범위 초과 값을 즉시 reject함

- 현재 구현은 dirty toy-data에 대한 강제 형변환(coercion) 또는 범위 클램핑(clamping) 로직이 없으며, 검증 실패 시 전체 배치의 해당 파일 투영을 포기하는 구조임

- (+) grip_succeed 컬럼이 smallint 도메인 규칙(0/1)을 항상 준수
- (−) 원천 데이터의 타입/범위 오류가 DTO 단계에서 자동 보정되므로, upstream 품질 모니터링 대시보드에 별도 경고 규칙 추가 필요
- (−) 기존 toyDataSchema 계약이 암묵적으로 완화되므로, 차기 버전 마이그레이션 노트에 grip_succeed 전처리 정책 명시 필요

### Non-Goals
- read_grip_result 스키마 구조 변경 또는 신규 컬럼 추가
- 다른 페이로드 필드(objects, robot_tf 등)의 dirty-data 처리 로직 도입
- Event Store 기록 실패 시 배치 롤백 또는 보상 트랜잭션 구현
