- read_grip_result 스키마의 object_name: varchar("object_name").notNull()은 빈 배열 시 null 삽입을 구조적으로 차단하지만, 현재 예외 던지기 방식이 가용성을 해침.

- 현재 GripResultProjector는 checkIntegrity()를 미구현하여 map() 단계에서 예외가 발생하면 트랜잭션 전체를 중단시킴.

### Decision Drivers
- 배치 처리 가용성 (Poison Event 격리 및 정상 이벤트 투영 보장)
- Read Model 정합성 엄격도 (object_name notNull 제약 유지 여부)
- 기존 구현 패턴 일관성 (MultiModalProjector.checkIntegrity 참조 및 CatchUpRunner 동작 방식)

### Considered Options
#### checkIntegrity 도입 및 map() 예외 제거 (Read Model 내 정합성 위임)
- 접근: GripResultProjector에 checkIntegrity() 구현, map()에서 예외 던지기 제거하고 objectName을 null 또는 기본값으로 설정. read_grip_result 스키마의 notNull 제약을 유지하려면 checkIntegrity에서 위반 시 IntegrityViolation 반환하여 CatchUpRunner가 롤백 없이 로그만 기록하도록 함.
- 제안 필드: object_name, checkIntegrity
- 트레이드오프: 배치 가용성 확보 및 poison event 격리 가능. object_name null 시 조회 로직 별도 처리 필요. 기존 notNull 제약 유지로 정합성 검사 단계에서 차단해야 함.
```typescript
map()에서 if (payload.objects.length === 0) throw ... 제거하고 objectName: payload.objects[0]?.class_name ?? null로 변경. checkIntegrity()에서 if (!row.objectName) return [{ ruleName: "object_nameNotNull", affectedColumns: ["object_name"], observedValue: null, expected: "non-null string", detail: "objects 배열이 비어 object_name이 누락됨." }]; 추가.
```

#### toyDataSchema 강제 검증 + 개별 이벤트 격리 처리 (발생원 차단)
- 접근: toyDataSchema의 objects 필드에 .min(1) 추가하여 구조 단계에서 차단. CatchUpRunner 단위 조정으로 개별 이벤트별 트랜잭션 또는 poison queue 분리.
- 제안 필드: objects.min(1), catchUpRunner.batchSize
- 트레이드오프: 결함 이벤트 발생 시 즉시 차단되나, 기존 외부 시스템 데이터 변경 불가 시 리스크. 배치 단위 조정 시 처리량 저하 가능.
```typescript

```
