- read_multimodal 프로젝트터는 동일 이벤트에서 미디어 파일명을 매핑할 때 빈 objects 체크를 수행하지 않아 정상 처리되나, grip-result의 롤백으로 인해 전체 파이프라인이 차단됨 [corr:5db691ee-6b76-4d34-879c-29a45a20aeb6]
- 현재 read_grip_result 스키마에서 object_name이 notNull()로 정의되어 있어, 빈 객체 배열에 대한 null 허용 여부가 구조적/구현적 불일치를 초래함 [corr:5db691ee-6b76-4d34-879c-29a45a20aeb6]

### Decision Drivers
- 배치 처리 연속성: Poison Event로 인한 전체 트랜잭션 롤백 방지 및 정상 이벤트의 지속적 투영 보장
- 데이터 정합성: object_name 결손 시 Read Model의 downstream 조회/분석에 미치는 영향 최소화
- 구현 복잡도: 기존 Drizzle 스키마 및 프로젝트터 수정 범위의 최소화

### Considered Options
#### nullify_object_name (방어적 매핑)
- 접근: GripResultProjector.map()의 빈 배열 체크를 경고(log.warn)로 변경하고, objectName에 null을 할당. Drizzle 스키마의 object_name을 nullable로 변경.
- 제안 필드: read_grip_result.object_name, grip-result.projector.ts.map
- 트레이드오프: 재투영 비용 낮음, Poison Event 차단 해소. 리스크: downstream에서 null 처리 필요, 데이터 품질 저하 가능성. Driver 1(연속성)과 Driver 3(복잡도)에서 우위.
```typescript
if (payload.objects.length === 0) { this.logger.warn({ action: LogAction.MAP_FAILED, [LogContext.EVENT_ID]: event.eventId }, objects 비어 있음 - null 매핑); return { ...baseRow, objectName: null }; }
```

#### skip_on_empty (사건 격리/스킵)
- 접근: GripResultProjector에서 빈 배열 시 SkipEventError를 던지거나 map()이 null을 반환하도록 변경하여 CatchUpRunner가 해당 이벤트를 건너뛰고 다음 배치로 진행.
- 제안 필드: grip-result.projector.ts.map, catch-up.runner.ts
- 트레이드오프: 트랜잭션 롤백 방지, 정상 이벤트 처리 보장. 리스크: 스킵된 이벤트 추적 필요, Dead Letter Queue 연동 복잡도 증가. Driver 1(연속성)에서 우위, Driver 2(정합성)에서 스킵된 데이터 누락 가능성.
```typescript
if (payload.objects.length === 0) { throw new SkipEventError(empty objects in ${event.eventId}); }
```

#### strict_rollback (기존 유지) [기각 대안]
- 접근: 현재 구현을 그대로 유지하여 빈 objects 이벤트를 즉시 차단.
- 제안 필드: grip-result.projector.ts.map
- 트레이드오프: Driver 1(연속성)에서 실패. Poison Event가 정상 배치까지 지연시켜 시스템 가용성을 해침.

### Decision Outcome
nullify_object_name (방어적 매핑) - 배치 처리 연속성(Driver 1)을 확보하면서도, Drizzle 스키마의 nullable 허용과 함께 null 값을 명시적으로 처리함으로써 데이터 정합성(Driver 2)을 유지할 수 있음.

### Consequences
- (+) Poison Event 차단 해소, 전체 배치 트랜잭션 롤백 방지
- (+) 정상 이벤트의 실시간 투영 보장
- (−) object_name이 null인 행이 생성되어 downstream 조회 시 null 체크 로직 추가 필요
- (−) 빈 objects 이벤트의 원본 데이터 누락 가능성

### Non-Goals
- ES 스키마(GripAttemptRecorded) 변경
- read_multimodal Read Model 수정
- Dead Letter Queue 인프라 구축
