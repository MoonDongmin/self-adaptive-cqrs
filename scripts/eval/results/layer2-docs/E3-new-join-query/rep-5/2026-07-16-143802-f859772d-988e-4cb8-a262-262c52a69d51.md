- MultiModalProjector.map() 구현체에서 image2dUri와 videoUri를 명시적으로 null로 할당하고 있어 URI 매핑 로직이 누락된 상태임. [corr:ca393aaf-95c2-4d94-9fd8-55356de6a4b1]
- 두 Read Model의 기본키가 (scene_key, attempt_num)으로 동일하여 1:1 매핑이 가능하나, 현재 Insight 카드 조회 로직은 단일 Read Model을 대상으로 설계되어 조인 또는 통합 테이블이 없으면 miss로 처리됨. [corr:97890cbb-f74d-4cbc-827e-73c9f0b6bef1]
- GripResultProjector는 파지 데이터만 투영하고 있으며, 미디어 URI 생성/할당 책임이 MultiModalProjector에 고립되어 있어 통합 뷰 제공 시 양쪽 프로젝터 수정이 필요함. [corr:f859772d-988e-4cb8-a262-262c52a69d51]

### Considered Options
#### read_multimodal에 파지 결과 필드 추가 (통합 보강)
- 접근: src/shared/database/schema/service/read-multimodal.ts에 gripSucceed, grip2dPose 추가. MultiModalProjector.map()에서 해당 필드 매핑.
- 제안 필드: grip_succeed, grip_2d_pose
- 트레이드오프: 단일 테이블 조회로 Insight 카드 응답 지연 최소화. 다만 read_multimodal의 도메인 책임이 파지 결과까지 확장되어 단일 책임 원칙 약화, read_grip_result와 데이터 중복 발생.

#### 신규 read_grip_insight 테이블 생성 (전용 분리)
