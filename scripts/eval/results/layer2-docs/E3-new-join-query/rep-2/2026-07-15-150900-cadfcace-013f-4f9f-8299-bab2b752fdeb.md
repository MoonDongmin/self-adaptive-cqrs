### Considered Options
#### 기존 read_multimodal 테이블에 파지 결과 컬럼 추가 및 MultiModalProjector 보강
- 접근: src/shared/database/schema/service/read-multimodal.ts에 grip_succeed, object_name, grip_2d_pose 등 핵심 파지 필드 추가. src/projection/projector/multimodal.projector.ts의 map()에서 해당 필드를 페이로드에서 직접 추출하여 채움.
- 제안 필드: grip_succeed, object_name, grip_2d_pose
- 트레이드오프: 재투영 비용이 낮고 단일 테이블로 조회 성능이 최적화됨. 하지만 미디어 전용 테이블에 파지 도메인 필드가 혼재되어 도메인 경계가 흐려질 수 있음.

#### 신규 통합 Read Model read_insight_card 생성 및 전용 Projector 구현
- 접근: src/shared/database/schema/service/read-insight-card.ts에 통합 스키마 정의. src/projection/projector/insight-card.projector.ts를 신규 생성하여 GripAttemptRecorded 이벤트에서 파지/미디어 데이터를 한 번에 매핑. 기존 테이블은 유지하되 조회용 뷰로 전환.
- 제안 필드: scene_key, attempt_num, object_name, grip_succeed, image_2d_file_name, video_file_name
- 트레이드오프: 도메인 경계가 명확하고 확장성이 우수함. 하지만 신규 테이블 마이그레이션 비용과 기존 투영 파이프라인 병렬화 리스크가 존재함.

### Decision Outcome
기존 read_multimodal 테이블에 파지 결과 컬럼 추가 및 MultiModalProjector 보강

### Consequences
- (+) 단일 쿼리로 파지 결과와 미디어 경로 동시 조회 가능
- (+) 기존 API 레이어 수정 최소화
- (+) 재투영 비용 절감
- (−) 미디어 테이블에 파지 필드 혼재로 도메인 경계 약화
- (−) 향후 파지/미디어가 독립적으로 진화할 경우 테이블 리팩토링 필요성 대두

### Non-Goals
- image_2d_uri/video_uri 실제 S3/OSS 매핑 로직 구현
- 실시간 스트리밍 지원
- 기존 read_grip_result 테이블 삭제
