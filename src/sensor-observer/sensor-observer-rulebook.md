# 센서 이상값 판정 룰북 v4 (llm-only 관찰자용)

> 이 문서가 판정 권한의 전부다. 이상 판정의 근거는 아래 R1~R6 뿐이며, reason 에는
> 반드시 rule ID(R1~R6)를 인용한다. 여기와 베이스라인의 rule 에 없는 임계값·규칙을
> 발명하지 마라. 특히 베이스라인 하단 "분포 통계"의 관측 클러스터 수치(예: 0.1998)는
> 참고 정보일 뿐 임계값이 아니다 — 그것을 근거로 한 판정은 무효다.

## 판정 절차 — 산수는 전부 서면으로, 그 밖에는 조용히

**아래 CHECK / R6-CHECK 라인과 위반 요약 외의 산문은 한 글자도 쓰지 마라. 검사 수행
과정 서술·통과 서술·정상 나열("모든 레코드에서 위반 없음" 같은 문장 포함)은 전부
금지다.** 범위 비교를 암산으로 하면 경계선 위반을 놓친다 — 반드시 값을 라인으로
추출한 뒤 그 라인의 값만 보고 비교하라.

### 1단계 — 레코드마다 CHECK 라인 정확히 한 줄 (생략 금지)

배치의 **모든 레코드**에 대해, 등장 순서대로 아래 형식의 CHECK 라인을 정확히 한 줄씩
출력하라. 이 라인이 없는 레코드의 판정은 무효다. 값은 레코드 JSON 에서 복사한다.
z8[...] 에는 그 레코드 `grip3dPose` 의 z1..z8 여덟 값을 **순서대로 전부**, 각각 소수
3자리로 반올림해 적는다 — 최솟값·최댓값을 원문에서 암산으로 고르지 마라. min/max 는
**네가 방금 적은 z8 목록 안에서** 골라 뒤이어 적는다(복사 먼저, 선택은 그 다음).
CHECK 라인 수는 배치 레코드 수와 **정확히 같아야** 한다(중복·발명·생략 금지).
**아래 출력 예시의 수치(0.058, 0.066, 0.177 등)는 가상의 예시일 뿐이다 — 예시 수치를
네 CHECK/R6-CHECK 라인에 복사하는 것은 추출 오류다. 모든 수치는 (A) 배치의 레코드
JSON 에서만 가져온다.**

`CHECK <scene 끝 5자리>#<attempt>: s=<gripSucceed> z8[<z1>,<z2>,<z3>,<z4>,<z5>,<z6>,<z7>,<z8>] min=<minz> max=<maxz> px[<xl>,<xr>,<yl>,<yr>] t[<x>,<y>,<z>]`

**값 추출 시 필드 혼동 금지 (실측된 오판 원인):**
- minz/maxz 는 `grip3dPose` 에서 **키 이름이 z 로 시작하는 z1..z8 만** 후보다.
  x1..x8, y1..y8 은 절대 후보가 아니다 (x 는 음수가 정상인 축이다 — x 값을 z 로
  옮겨 적으면 가짜 음수 깊이가 만들어진다).
- t 는 `robotTf.translation_3x1` 배열이며 순서대로 [0]=x, [1]=y, [2]=z 다.
  배열 셋째 값(z, 보통 1.0 안팎)을 y 로 옮겨 적지 마라.
- px 는 `grip2dPose` 의 xl, xr, yl, yr 네 값이다.

### 2단계 — CHECK 라인의 값만 보고 규칙 판정

- R1 gripSucceed 도메인 — `s` 가 0 또는 1 이 아니면 위반.
- R2 깊이 물리 하한 — `minz` ≤ 0 이면 위반 (깊이 ≤ 0 은 물리적으로 불가능).
- R3 2D 픽셀 이미지 범위 — `px` 의 xl·xr 이 [0, 1920] 밖이거나 yl·yr 이 [0, 1110]
  밖이면 위반.
- R4 회전행렬 유효성 — `robotTf` 의 rotation_3x3(행우선 9개)에서 각 열의
  제곱합(L2 노름²)이 1±0.04 를 벗어나거나, 열 부호가 통째로 반전(반사행렬,
  det=-1)되거나 직교성이 깨졌으면 위반. (CHECK 라인 밖에서 조용히 검사한다 —
  확신 없으면 판정하지 마라.)
- R5 성공-포즈 정합 — `s`=1(성공) 레코드만 적용한다. 복합 비교(축 3개 + 깊이 범위)는
  암산으로 하면 반드시 빠뜨린다 — `s`=1 인 레코드마다 아래 R5-CHECK 라인을 정확히
  한 줄씩 출력하라(생략 금지 — 이 라인이 없으면 그 레코드의 R5 판정은 무효다.
  각 항목은 CHECK 라인의 값을 그대로 가져와 범위와 비교하고 OK 또는 X 로 표기):
  `R5-CHECK <scene 끝 5자리>#<attempt>: tx=<x>∈[-0.50,0.50]=<OK|X> ty=<y>∈[0.65,0.95]=<OK|X> tz=<z>∈[0.95,1.15]=<OK|X> zmin=<minz>≥0.01=<OK|X> zmax=<maxz>≤0.30=<OK|X>`
  X 가 하나라도 있으면 위반(잡을 수 없는 위치/깊이에서 성공은 모순). t 의 x,y,z 는
  각각 자기 축의 범위와만 비교하라(필드 혼동 금지). `s`=0(실패) 레코드는 R5-CHECK 를
  쓰지 않는다 — 범위 밖 값이 자연 노이즈일 수 있으므로 R5 를 적용하지 않는다.
- R6 같은 scene 급변 — **sceneKey 문자열이 완전히 동일한** 레코드 쌍((C) 이월
  레코드 포함)에만 적용한다. R6 를 시작하기 전에 먼저 배치의 sceneKey 목록에서
  두 번 이상 등장하는 sceneKey 만 골라라. 그런 sceneKey 가 하나도 없으면 R6 는
  검사할 쌍이 없는 것이다 — R6-CHECK 를 0줄 쓰고 곧장 다음으로 넘어가라.
  sceneKey 가 다른 인접 레코드끼리의 비교·체인 비교는 절대 금지다(objectName 이
  같아도 scene 이 다르면 장면 자체가 다르므로 비교 대상이 아니다).
  같은 scene 쌍마다 아래 계산 라인을 정확히 한 줄씩 출력하라(생략 금지 — 이 라인이
  없으면 R6 판정 자체가 무효다. 수치는 소수 3자리로 반올림).
  **z대푯값은 8개 평균을 암산하지 말고, 그 레코드 CHECK 라인에 이미 적은 minz·maxz 의
  중점 (minz+maxz)/2 로 계산한다** — 두 레코드 각각의 중점을 구해 차이를 비교한다:
  `R6-CHECK <scene 끝 5자리>: (<선행 minz>+<선행 maxz>)/2=<선행 중점> → (<후행 minz>+<후행 maxz>)/2=<후행 중점>, Δ=<차이> vs 0.10`
  Δ > 0.10 m 이고 objectName 이 같으면 위반. objectName 전환 등 장면 변화로
  설명되면 정상. robotTfTranslation 의 attempt 간 이동은 마운트 변경으로 정상 —
  급변 근거 금지. **R6 위반 판정은 sceneKey 가 같은 두 레코드의 쌍에서만 가능하다.
  sceneKey 가 다른 레코드끼리의 비교에서 Δ > 0.10 이 나와도 절대 위반이 아니다 —
  scene 이 다르면 물체 배치가 달라 값대가 다른 것이 정상이다.**

## 오판 방지 (하나라도 어기면 그 판정은 무효)

1. 위반 주장 전, CHECK 라인에 적힌 관측값과 경계값을 나란히 놓고 **부등호가 참인지
   재확인**하라 (예: "0.178 > 0.1998" 은 거짓이므로 판정 불가). 부등호가 거짓이면 버려라.
2. '처음 보는 값(novelty)'은 이상이 아니다. 클러스터 밖·분포 밖이라는 이유만으로
   판정하지 마라(새 마운트·새 물체일 수 있다).
3. 인용할 관측값 숫자를 레코드에서 특정할 수 없으면 그 판정은 버려라.
4. 애매하면 정상(triggered=false)이다. CHECK 라인은 값 추출이지 위반 탐색 할당량이
   아니다 — 모든 CHECK 라인이 범위 안이면 위반 요약 0줄에 triggered=false 가 정답이다.
5. X 로 표기한 항목은 위반 요약에 올리기 전, 레코드 JSON **원문에서 그 필드를 다시
   찾아** CHECK 라인의 값과 대조하라. 원문의 해당 필드에 그 값이 실재하지 않으면
   추출 오류다(다른 필드의 값을 옮겨 적은 것) — 그 항목은 무효로 하고 OK 로 정정하라.

## 출력 계약

**응답의 첫 글자는 반드시 `CHECK` 로 시작한다.** "R1 위반 —" 같은 서술형 문장으로
응답을 시작하는 것은 계약 위반이다 — 위반 요약은 CHECK/R6-CHECK 라인들 뒤에만 올 수 있다.

출력은 아래 다섯 부분이 전부이며 이 순서를 지킨다. 다른 산문은 전부 금지다.

1. CHECK 라인들 — 레코드당 정확히 한 줄, 배치 레코드 수와 동수.
2. R5-CHECK 라인들 — `s`=1 레코드당 정확히 한 줄.
3. R6-CHECK 계산 라인들 — 같은 scene 쌍이 있을 때만.
4. 위반 요약 — 위반된 레코드만 한 줄씩(rule ID + 관측값 인용 + 부등호 비교), 최대 8줄.
   위반이 하나도 없으면 이 부분을 통째로 생략한다.
5. JSON 코드블록 정확히 하나.

`offendingSceneKeys` 에는 위반 레코드의 `sceneKey` 값을 레코드 JSON 에서 **글자
그대로 복사**해 담는다(발명·요약·수정 금지). 위반 레코드를 특정할 수 없으면
트리거하지 마라.
